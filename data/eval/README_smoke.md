# 群体画像冒烟测试集 v1.0

这是一套用于 6Gang 群体画像的首轮冒烟测试，共 25 个用例：5 个共同比较场景分别发送给 C1-C5 五个画像。

## 使用方式

机器执行时使用 `test_cases_persona_smoke_v1.json`。项目主分支的 `seed-personas.ts` 按 C1-C5 对应数字 1-5，因此本文件默认使用这个映射。项目评测脚本要求 `target_id` 与服务端画像 ID 一致，若服务端没有按主分支重新初始化，必须先调整 JSON 中的 `target_id`，不需要改题目。

示例：

```bash
python3 scripts/eval_run_v3.py data/eval/test_cases_persona_smoke_v1.json --limit 5 --no-judge
```

上面的命令只用于先检查接口能否返回回答。完成收集后，再去掉 `--no-judge` 执行自动评分。正式跑题前，需要确认服务端已经部署主分支的5个画像。当前线上地址 `http://49.232.59.125` 仍返回旧版8个画像，ID 1-4 不存在，不能直接运行本题库；本地当前主分支服务应使用 `http://localhost:3000`。

## 人工评分规则

每个回答按项目现有的 7 个维度评分，范围为 1-5 分：

| 维度 | 通过参考 |
|---|---|
| 人设一致性 | 至少 4 分，核心立场符合目标画像 |
| 专业准确性 | 至少 3 分，机制判断有合理依据 |
| 知识边界 | 至少 4 分，不把未知内容说成亲身经历 |
| 具体性 | 至少 3 分，最好有场景、行为或例子 |
| 情感真实性 | 至少 3 分，表达自然，不像统一模板 |
| 区分度 | 至少 3 分，不能和其他画像回答完全互换 |
| 深度 | 至少 3 分，能说明原因、影响或取舍 |

冒烟测试中，以下情况直接记为失败：

- 出现 `contradictions` 中的核心矛盾。
- 声称拥有题目没有提供的具体经历、战绩、游戏版本或事实。
- 五个画像对同一题几乎给出相同的价值判断，只更换了语气。
- 回答只有“看情况”“都可以”“挺好的”等泛化表达，没有解释。

## 题目设计

- Q01：具体场景叙述，检查行为、动机和人设锚点。
- Q02：产品立项取舍，检查画像是否能明确站队。
- Q03：玩法机制评价，检查画像是否有不同的判断逻辑。
- Q04：商业化态度，检查公平、社交、压力、战斗反馈或沉浸内容等差异。
- Q05：未知信息处理，检查知识边界和是否编造体验。

其中 Q02-Q04 应把五个画像的回答放在一起比较；Q05 主要看是否诚实说明未知信息，同时检查不同画像提出的验证方式是否符合其核心诉求。

## 当前限制

项目仓库中的题目数量和版本存在历史不一致，且服务端部署版本可能不是最新版本。因此这份文件是可执行的 v1 冒烟集，不能替代项目内部尚未公开的完整 150 题基线。执行前应确认画像 ID 映射和 API 版本。
