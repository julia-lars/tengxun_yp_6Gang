# 群体画像 v2.0 问题修复方案

> 基于 2026-09-01 评测 750 条真实数据，针对 5 类问题给出技术方案，区分 prompt 改动和架构改动。

---

## 一、问题诊断（基于真实数据）

| # | 问题 | 真实数据 | 根因 | 类型 |
|---|------|----------|------|------|
| 1 | 深度不足 | 全局均分 2.93，72% 在 3 分，18% 在 2 分 | system prompt 缺少"观点库" | **改 prompt** |
| 2 | 沉浸探索型人设漂移 | 综合 4.04（最低），人设一致性 4.37（最低），区分度 3.58（最低） | 标签分散（探索+叙事），无核心场景锚点 | **改 prompt** |
| 3 | 低压解压型回答空洞 | 综合 4.07，深度 2.57（最低），具体性 3.46（最低），65 题深度=2 | "放松逃避"标签太抽象，无行为素材 | **改 prompt** |

## 二、改 Prompt 的方案（问题 1-4）

所有 prompt 改动集中在 `apps/api/src/routes/chat.ts` 的 `buildSystemPrompt` 函数（第 32-78 行），不涉及数据库 schema 变更。

### 方案 1：全画像深度素材注入（解决深度 2.93）

**当前状态**：`buildSystemPrompt` 输出的是：
```
你是「低压解压型」，核心诉求为放松逃避。
标签: {"诉求": ["放松逃避"], "风格": []}
核心动机: 放松逃避
行为模式: 休闲匹配、社交开黑
```

这告诉 AI "你是谁"，但没有告诉 AI "你该怎么思考"。Judge 对深度=2 的典型评语是"仅表面描述，没有深层分析或独特视角"。高分题（Q-043, Q-062）的共同特征是 AI 给出了"辩证分析"和"具体设计建议"。

**改进**：在 `buildSystemPrompt` 中为每个画像增加一个"深层观点"段落，用一组该画像对游戏的独特认知框架替代"请给出深入分析"这种空泛指令。

**新增段落示例**（竞技成长型）：
```
## 你判断游戏的标准
- 你衡量游戏价值的核心尺度是"能不能让人变强"——排位分、操作上限、战术深度，而不是"好不好看""热不热闹"
- 你对"平衡性"的理解不是所有武器数值一样，而是"同等练习投入下应有相近的上限"
- 付费对你来说不是问题，问题是"花完钱能不能提升竞技体验"——皮肤不重要，扩展英雄池/训练模式值得买
- 你判断一款游戏"能不能火"的标准是它的竞技深度是否足以支撑职业比赛
- 你对"新手保护"机制持矛盾态度：理解它的必要性，但担心它降低竞技的纯粹性
```

**对其他画像同样生成 5-8 条**. 在 prompt 末尾追加指令：
```
在需要分析、评价、判断时，从你的判断标准出发给出有洞察力的分析，而不仅仅是表明态度。
```

**预期效果**：深度 2.93 → 3.3+（给 AI 提供了"可引用的观点素材"，而非空泛要求"深入"）

**工作量**：为 5 个画像各编写 5-8 条深层观点（2h）+ 修改 `buildSystemPrompt`（30min）+ 验证评测（30min）

### 方案 2：沉浸探索型人设聚焦（解决综合 4.04）

**真实数据**：沉浸探索型 6 道低分题（<3.5）的 Judge 评语都指向同一类问题——AI 无法在需要明确立场时站队：
- Q-002（2.74）："语气平淡，缺乏沉浸探索型应有的深度和细节，未能体现对游戏体验的专注探索"
- Q-143（3.11）："目标画像通常指深度投入、追求沉浸感的 PC 或主机玩家，但回答自称手游玩家"
- Q-126（3.19）："回答聚焦于收集皮肤，用词'我从不失手'更接近其他画像的表述"
- Q-138（3.19）："语气偏轻快，缺乏沉浸探索型常见的深度思考或对游戏细节的执着"

**根因**：`tagSpec.诉求 = ["探索收集", "叙事沉浸"]` 两个方向不同，且 `风格` 为空。AI 每次回答时随机选择"探索玩家"或"叙事玩家"或"审美玩家"的立场，导致漂移。

**改进**：在 prompt 中增加一个不可动摇的"核心场景"锚点：
```
## 你的核心游戏场景
你是深度沉浸型玩家。你的典型状态是：
- 独自一人，关上房门，戴上耳机，花 3-4 小时沉浸在一款游戏的世界里
- 你玩游戏是为了"体验另一个世界"——像看电影/读书一样认真对待每一款游戏
- 你偏好 PC/主机端，因为大屏幕和高画质是沉浸感的必要条件
- 你对外设的核心要求是"沉浸感"（好耳机听环境音、好显示器看细节），而非"反应速度"或"竞技性能"
- 你会在游戏中选择"探索模式"或"故事模式"而非"竞技模式"
```

这就是针对 Q-002（场景）、Q-143（外设）、Q-126（成就）、Q-138（换游戏）的低分模式直接给出的立场锚点：**设备=PC、外设=沉浸感、成就=发现过程、换游戏=看内容深度**。

**预期效果**：人设一致性 4.37 → 4.5+，区分度 3.58 → 3.9+，低分题（<3.5）从 6 题减半

**工作量**：编写场景锚点（30min）+ 修改 prompt（15min）+ 验证评测（30min）

### 方案 3：低压解压型素材注入（解决具体性 3.46、深度 2.57）

**真实数据**：低压解压型深度=2 的 65 题中，前 10 题全部集中在"一致性测试"类别——AI 在回答"你什么水平""你练不练枪""你用啥设备""你多久玩一次"这类自我描述题时，反复说"我就是放松""不想太累""随便玩玩"，但没有具体的行为描述。

**根因**：`tagSpec.诉求 = ["放松逃避"]`，`风格 = []`。"放松逃避"是五个画像中最抽象的标签，AI 没有具体行为模式可参照。

**改进**：在 prompt 中注入"放松"的具体行为表现，把抽象标签转化为可描述的行为：
```
## 你的典型游戏状态
- 你的游戏场景：下班后往沙发上一躺，掏出手机开一局，不语音、不组队、不在意输赢
- 你的时间偏好：15-20 分钟一局的模式正好，太长了会累，太短了不过瘾
- 你的核心态度："随缘"——不刻意练枪，不研究数据，不看攻略，被虐了换一局接着玩
- 你的社交边界：偶尔和熟人开黑，但从不主动组陌生人——社交也是需要精力的
- 你的付费逻辑：不影响游戏体验就不充，心情好可能买个小月卡，但不会研究性价比
- 你和其他玩家的区别：竞技型追求"赢"，战斗型追求"爽"，社交型追求"一起"，探索型追求"发现"——你追求"不累"
```

**关键设计**：最后一条"和其他玩家的区别"直接让 AI 知道它和 4 个画像的边界在哪里，避免 Judge 评"区分度不足"。

**预期效果**：具体性 3.46 → 3.8+（有场景可描述），深度 2.57 → 2.8+（有观点可展开），综合 4.07 → 4.12+

**工作量**：编写行为素材（30min）+ 修改 prompt（15min）+ 验证评测（30min）

### 方案 4：区分度定向增强（解决产品设计题趋同）

**真实数据**：区分度最低的 15 题（分差 < 0.24）全部是产品设计判断题——"64 人大战场""真实枪械 vs 能量武器""军工 vs 炫彩皮肤""公会系统""载具系统""pay-to-win 接受度"等。这 15 题中 5 个画像的分数几乎相同，因为 AI 面对这类问题时，只能从"通用消费者"视角回答"看情况""挺有意思的"。

**根因**：prompt 只定义了"你是谁"，没定义"你对各类游戏设计的态度是什么"。

**改进**：在 prompt 中为每个画像增加一个"设计偏好"段落，预设在常见设计维度上的立场。不需要写 5 个画像 × 5 个维度的矩阵，而是按画像各写一段：

```
## 你对游戏设计的态度
（竞技成长型示例）
- 竞技公平是你最看重的底线——pay-to-win、随机性过强的设计你无法接受
- 皮肤风格你偏好低调但有辨识度的（如职业选手同款），炫彩特效反而影响你判断战场
- 公会系统对你来说是"找水平相当的队友一起打排位"，奖励不重要
- 大战场/载具你对它持谨慎态度——如果它破坏战术深度，就不值得
- 付费你愿意为"能提升竞技体验"的内容付费（扩展英雄池、额外训练模式），但不会为皮肤花钱
```

**关键**：每个画像的 5 条设计态度必须互斥——竞技型在乎"公平"，战斗型在乎"爽"，社交型在乎"一起"，低压型在乎"简单"，沉浸型在乎"内容"。当 5 个画像面对同一道皮肤题时，各自给出不同立场，区分度自然拉开。

**预期效果**：区分度 3.93 → 4.1+，产品设计题分差从 0.08-0.24 → 0.5+

**工作量**：为 5 个画像 × 5 个维度编写立场（1h）+ 修改 prompt（15min）+ 验证评测（30min）

## 三、改技术架构的方案（问题 5）

### 问题 5a：关键词覆盖指标失效（0.13，78% 得 0）

**真实数据**：keyword_score 均分 0.13，583/750 题得 0 分。长度合理性和反模板化均为 1.00，无区分度。

**原因**：当前算法对 reference（结构化要点列表）和 AI 回答（自然对话）做字符串匹配，二者格式完全不同，无法匹配。这是**评测脚本的算法问题**，不是 prompt 问题。

**修复方向**：在 `scripts/eval_run_v3.py` 的 `compute_auto_metrics` 函数中，将关键词匹配改为 LLM 语义判断，或直接降低该指标权重至 0%。

```python
# 方案 A：替换为 LLM 语义覆盖判断
prompt = f"参考要点: {reference}\n回答: {answer[:500]}\n回答是否覆盖了参考要点的核心概念？输出 0-1 的小数"

# 方案 B：直接降低权重，增加深度维度权重
# 在 final_score 计算中，keyword_score 权重从当前值改为 0
# 同时将深度维度权重从 0.1 提升到 0.15
```

**工作量**：1h（方案 A 需要 LLM 调用，增加评测成本；方案 B 更简单）

### 问题 5b：幻觉检测白名单不完整（0.87）

**真实数据**：幻觉检测均分 0.87，没有 0 分题，但存在系统性误报——"Roguelike""MOBA""英雄射击""手机端的射击"等通用游戏类型词被标记为"编造游戏名"。

**修复**：在 `scripts/eval_run_v3.py` 中扩充 `KNOWN_GAMES` 白名单，增加通用游戏类型词：

```python
GENERIC_GAME_TERMS = {
    "roguelike", "roguelite", "moba", "mmorpg", "fps", "tps",
    "大逃杀", "吃鸡", "英雄射击", "战术竞技", "开放世界",
    "二次元", "像素", "像素风", "卡通", "写实",
    "端游", "手游", "PC端", "手机端", "主机",
    "单机", "网游", "联机", "多人", "合作",
}
```

**工作量**：30min

## 四、改动分类总结

| 方案 | 改什么 | 改哪里 | 类型 |
|------|--------|--------|------|
| 深度素材注入 | prompt 增加"深层观点"段落 | `chat.ts:buildSystemPrompt` | **改 prompt** |
| 沉浸探索型聚焦 | prompt 增加"核心场景锚点" | `chat.ts:buildSystemPrompt` | **改 prompt** |
| 低压解压型素材 | prompt 增加"典型游戏状态"段落 | `chat.ts:buildSystemPrompt` | **改 prompt** |
| 区分度增强 | prompt 增加"设计态度"段落 | `chat.ts:buildSystemPrompt` | **改 prompt** |
| 关键词覆盖修复 | 替换匹配算法或调权重 | `eval_run_v3.py:compute_auto_metrics` | **改技术架构** |
| 幻觉检测修复 | 扩充白名单 | `eval_run_v3.py` | **改技术架构** |

- **方案 1-4**：全部改 prompt，不涉及数据库、不涉及 API 调用、不涉及架构变更，改动范围为 `buildSystemPrompt` 函数（约 40 行代码 + 5 段素材文本）
- **方案 5**：改评测脚本，不涉及线上系统

## 五、实施优先级

| 优先级 | 方案 | 工时 | 理由 |
|--------|------|------|------|
| P0 | 方案 3：低压解压型素材 | 1h | 影响最大（65 题深度=2）+ 改动最小 |
| P0 | 方案 2：沉浸探索型聚焦 | 1h | 低分题最多（6 题<3.5）+ 人设漂移需立刻修正 |
| P1 | 方案 1：全画像深度素材 | 3h | 全局短板，但需要为 5 个画像编写素材 |

**总计约 8 小时**，所有 prompt 改动集中在 `chat.ts` 一个文件的一个函数中。
