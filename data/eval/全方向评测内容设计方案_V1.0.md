## 一、A 层：聚类真实性评测内容（40 分）

### 1.1 评测内容总览

A 层不依赖"测试题"，而是依赖**聚类验证数据集 + 统计检验流程**。

| 子维度 | 分值 | 评测内容类型 | 需要准备的素材 |
| --- | ---: | --- | --- |
| A1 类内一致性 | 10 | 统计计算 | 玩家级 M1–M5 标签向量 + Embedding 向量 |
| A2 类间区分度 | 10 | 统计计算 + 矩阵 | 同上 + Cluster 质心向量 |
| A3 聚类稳定性 | 8 | Bootstrap 实验 | 玩家级特征矩阵 + 参数网格配置 |
| A4 玩家级一致性 | 7 | 统计计算 | speaker_id 映射表 + 片段级 cluster 标签 |
| A5 Cluster Coverage | 3 | 统计计算 | 片段级 cluster 标签 |
| A6 聚类可解释性 | 2 | 人工评分 | 可解释性评分表 + 人工评估者 |

### 1.2 A1/A2：类内一致性与类间区分度

**需要的素材**：

```text
素材名称：player_feature_matrix.json
数据粒度：玩家级（speaker_id 聚合）
包含字段：
  - speaker_id
  - M1 标签向量（one-hot / 多热）
  - M2 标签向量
  - M3 标签向量
  - M4 标签向量
  - M5 标签向量
  - embedding 向量（768/1536 维）
  - cluster_label（聚类结果）
  - 结构化标签（能力等级、风格、平台、模式等）
```

**计算流程**：

```text
输入：player_feature_matrix.json
  ↓
对每个 cluster：
  计算 M1–M5 Cohesion（类内平均 pairwise 相似度）
  计算 Semantic Cohesion（类内平均 cosine 相似度）
  ↓
对所有 cluster pair：
  计算 M1–M5 Separation Ratio（D_between / D_within）
  计算 Semantic Separation Ratio
  ↓
输出：
  A1 分数（各 M 层 Cohesion 加权）
  A2 分数（各 M 层 Separation Ratio 加权）
  Cluster Separation Matrix（所有 pair 的区分度热力图）
```

**输出文件**：`A1_A2_cohesion_separation_report.json`

### 1.3 A3：聚类稳定性

**需要的素材**：

```text
素材名称：stability_test_config.json
配置项：
  - bootstrap_iterations: 50
  - sample_ratio: 0.80
  - resample_unit: "player"  （以玩家为单位重采样，非片段）
  - random_seeds: [42, 123, 456, ...]  （50 个固定种子，保证可复现）
  
  - parameter_grid: {
      "min_cluster_size": [5, 10, 15, 20, 30],
      "min_samples": [1, 3, 5],
      "cluster_selection_method": ["eom", "leaf"]
    }
```

**执行流程**：

```text
Phase 1 — Bootstrap ARI：
  for i in 1..50:
    随机抽取 80% 玩家
    重新执行完整聚类 Pipeline
    计算 ARI(C_baseline, C_i)（匈牙利算法匹配标签）
  输出：Bootstrap ARI = mean(ARI_1..ARI_50)

Phase 2 — Cluster Jaccard：
  for 每个 Baseline cluster：
    计算 50 次 Bootstrap 中该 cluster 的平均 Jaccard
  输出：Cluster Jaccard = mean(所有 cluster Jaccard)

Phase 3 — Parameter Robustness：
  for 每种参数组合（30 种）：
    运行聚类
    计算 ARI(C_baseline, C_param)
  输出：Parameter Robustness = mean(所有组合 ARI)
```

**输出文件**：`A3_stability_report.json`

### 1.4 A4：玩家级一致性

**需要的素材**：

```text
素材名称：segment_cluster_mapping.json
数据粒度：片段级
包含字段：
  - segment_id
  - speaker_id（玩家 ID）
  - cluster_label（该片段被分配到的 cluster）
```

**计算流程**：

```text
按 speaker_id 聚合：
  对每个玩家 p：
    Purity_p = max_c(n_pc) / sum_c(n_pc)
    Entropy_p = -sum(p_pc * log(p_pc)) / log(K)
  
  对每个 cluster c：
    Dominance_c = max_p(n_pc) / n_c
    if Dominance_c >= 0.70 → Player Dominance Warning

输出：
  Player Purity = mean(Purity_p)
  Player Entropy = 1 - mean(NormalizedEntropy_p)
  Player Dominance Score = 1 - max(Dominance_c)
```

**输出文件**：`A4_player_consistency_report.json`

### 1.5 A5：Cluster Coverage

**需要的素材**：同 A4（`segment_cluster_mapping.json`）

```text
Segment Coverage = |segments with label ≠ -1| / |all segments|
Player Coverage = |players with at least 1 valid segment| / |all players|
```

**输出文件**：`A5_coverage_report.json`

### 1.6 A6：聚类可解释性

**需要的素材**：

```text
素材名称：cluster_interpretability_rubric.json
内容：
  - 每个 cluster 的 M1–M5 核心结论列表
  - 每条结论的证据引用（segment_id + 原文）
  - 人工评分表（1–5 分 × M1–M5 各层 × 每个 cluster）
```

**评分流程**：

```text
A6-1 Evidence-backed Claims：
  ClaimCoverage = 有 ≥2 条不同玩家证据的结论数 / 全部结论数

A6-2 Human Interpretability：
  至少 2 名评估者，对每个 cluster 的 M1–M5 可理解性打分
  Interpretability = mean(所有评分) 归一化到 0–100
  同时报告评估者间 ICC
```

**输出文件**：`A6_interpretability_report.json`

| 子维度 | 分值 | 评测内容类型 | 需要准备的素材 |

### 2.2 B1/B2/B3：证据覆盖、支持率与矛盾率

**核心素材：Persona Claim Evidence Matrix**

```text
素材名称：persona_claim_evidence_matrix.json
结构：
{
  "persona_id": "C1",
  "claims": [
    {
      "claim_id": "C1-001",
      "claim_text": "该群体高度重视竞技公平性",
      "importance": "core",           // core | important | auxiliary
      "primary_M_layer": "M1",
      "supporting_evidence": [
        {"segment_id": "S-1234", "speaker_id": "P01", "quote": "..."},
        {"segment_id": "S-5678", "speaker_id": "P15", "quote": "..."}
      ],
      "contradicting_evidence": [
        {"segment_id": "S-9012", "speaker_id": "P08", "quote": "..."}
      ],
      "support_rate": 0.85,           // 支持该 claim 的玩家占比
      "contradiction_severity": "none" // none | weak | strong
    }
  ]
}
```

**计算流程**：

```text
B1 Evidence Coverage：
  Coverage = |claims with ≥2 supporting evidence from different players| / |all claims|
  Diversity = mean(支持该 claim 的不同 speaker_id 数 / cluster 玩家数)
  B1 = 0.70 × Coverage + 0.30 × Diversity

B2 Evidence Support：
  SupportRate_i = 支持该 claim 的玩家数 / cluster 总玩家数
  B2 = mean(所有 claim 的 SupportRate)

B3 Contradiction：
  ContradictionRate = |claims with contradicting evidence| / |all claims|
  WeightedContradiction = sum(w_i × 1[有反证]) / sum(w_i)
  B3 = 100 × (1 − [0.60 × ContradictionRate + 0.40 × WeightedContradiction])
```

### 2.3 B4：画像区分度

**需要的素材**：

```text
素材名称：persona_claim_vectors.json
结构：
  - 每个 claim 的 embedding 向量
  - 每个 claim 的 cluster 归属
  - 每个 claim 在各 cluster 的 SupportRate
```

**计算流程**：

```text
B4-1 Unique Feature Rate：
  UFR_c = |claims 在 cluster c 的 SupportRate 显著高于其他 cluster| / |all claims in c|
  "显著高于" = SupportRate_c - max(SupportRate_other) >= 0.20

B4-2 Pairwise Profile Similarity：
  对每对画像 (i,j)：
    Sim_ij = |claims in i 在 j 中有高相似 claim| / |claims in i|
  全局 ProfileSimilarity = mean(所有 pair 的 Sim_ij)
  
B4 = 0.50 × UFR + 0.50 × (1 − ProfileSimilarity)
```

**输出文件**：`B_persona_validity_report.json`

### 2.5 B 层关键：Claim 提取规范

这是 B 层能跑起来的前提。每个 Persona 画像必须从自然语言描述拆成 **Atomic Claims**：

```text
Claim 提取规范：

1. 每个 claim 必须是单一可验证的断言
   ✅ "该群体在排位赛中优先选择主动进攻策略"
   ❌ "该群体喜欢竞技玩法"（太笼统）

2. 每个 claim 必须标注 M 层归属
   - M1 动机层：关于"为什么玩"的断言
   - M2 期待层：关于"希望游戏怎样"的断言
   - M3 认知层：关于"怎么看待游戏"的断言
   - M4 感受层：关于"玩的时候什么感觉"的断言
   - M5 行为层：关于"实际怎么做"的断言

3. 每个画像至少 10 个 claims，最多 25 个

4. 每个 claim 必须标注重要性：
   - core：去掉这个 claim，画像就不完整
   - important：对画像有显著贡献
   - auxiliary：辅助性描述

5. 不能出现"所有玩家都这样"的无效 claim
   反例："该群体认为外挂不好" → 所有玩家都这么认为，无效
```

### 4.2 D1：Test-Retest 实验设计

```text
素材名称：retest_sample_config.json
配置：
  - sample_size: 30 题 × 3 个画像 = 90 个样本
  - repeats: 3 次
  - 控制变量：
      prompt: 固定
      context: 固定
      model: 固定
      temperature: 固定（仅改变 random_seed）
  - 采样方式：分层随机（确保覆盖所有 M 层和所有 cluster）

执行：
  for 每个样本：
    for i in 1..3：
      用相同 prompt + 不同 seed 生成回答
      Judge 评分
  计算 ICC(2,1) + MAD
```

**输出文件**：`D1_test_retest_report.json`

### 4.3 D2：Judge Agreement 实验设计

```text
素材名称：judge_agreement_config.json
配置：
  - 样本：从 C 层评测结果中随机抽取 50 个回答
  - Judge 配置：
      Judge A: 当前生产 Judge（如 DeepSeek + 当前 Prompt）
      Judge B: 同模型 + 不同 temperature
      Judge C: 不同模型（如 Claude）+ 相同 Prompt

执行：
  每个 Judge 独立对同一批答案评分
  计算 ICC(2,k) 或 Krippendorff's α

重要提醒：
  Judge 间一致 ≠ Judge 与人工一致
  D2 高分 + D3 低分 = 所有 Judge 共享同样的系统性偏差
```

**输出文件**：`D2_judge_agreement_report.json`

### 4.4 D3：Human Agreement 实验设计

```text
素材名称：human_calibration_sample.json
配置：
  - 样本：从 C 层评测结果中抽取 10–20%（约 20 题 × 5 画像 = 100 个样本）
  - 人工评分者：至少 2 人
  - 评分标准：与 LLM Judge 使用完全相同的 rubric

执行：
  1. 人工评分者培训（对齐 rubric 理解）
  2. 独立评分
  3. 计算 Human vs AI Judge 的 ICC + Spearman
  4. 识别系统性分歧样本（|Human - AI| >= 2 分）
  5. 分析分歧原因，修正 Judge Prompt
```

**输出文件**：`D3_human_agreement_report.json`

### 4.5 D4：Judge Robustness 实验设计

```text
素材名称：judge_robustness_config.json
配置：
  - Prompt 变体（3 种）：
      Prompt A: 当前生产版本
      Prompt B: 改变措辞但不改变评分维度
      Prompt C: 改变评分维度顺序但不改变内容
  - Model 变体（2 种，可选）：
      Model A: DeepSeek
      Model B: Claude

执行：
  同一批答案 × 3 种 Prompt 分别评分
  计算 CV = σ / μ
  若 CV > 0.25 → Judge 对 Prompt 措辞敏感
  若 Model 间最大差异 > 1.0（1-5 分制）→ Judge 对 Model 敏感
```

**输出文件**：`D4_judge_robustness_report.json`
