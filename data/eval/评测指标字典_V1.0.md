### 0.2 指标分类

| 类别 | 说明 | 涉及指标 |
| --- | --- | --- |
| **第一类：核心连续指标** | 可直接从数据分布计算，无需人工标注 | A1-1~A1-6, A2-1~A2-6, A3-1~A3-3, A4-1~A4-3, A5-1~A5-2, C6 |
| **第二类：证据指标** | 需要 claim annotation 和证据链 | A6-1, B1, B2, B3, B4 |
| **第三类：LLM Judge 指标** | 需要 rubric → judge → 人工校准 → reliability check | C1, C2, C3, C4, C5, A6-2, D1~D4 |

### 0.3 评分转换统一规则

所有底层指标原始值统一转换为 **0–100** 分数，再乘以指标权重计入总分。

| 原始值类型 | 转换方式 | 示例 |
| --- | --- | --- |
| 连续值 ∈ [0,1] | 直接 ×100 | ARI=0.82 → 82 |
| 比率/覆盖率 ∈ [0,1] | 直接 ×100 | Coverage=0.91 → 91 |
| 反向指标（越低越好） | 100 × (1 − 原始值) | Contradiction=0.12 → 88 |
| 距离值（需归一化） | 先归一化到 [0,1] 再 ×100 | 见各指标具体公式 |
| ICC ∈ [0,1] | 直接 ×100 | ICC=0.87 → 87 |

### 0.4 阈值确定原则

**V1 第一轮不急于定义所有绝对阈值。** 分三步走：

1. **第一阶段（Baseline）**：跑当前系统，得到所有指标的分布
2. **第二阶段（校准）**：引入人工判断 / 专家黄金案例，标注"可接受 vs 不可接受"
3. **第三阶段（定标）**：根据校准结果建立阈值

当前权重已锁定。阈值标注为"待校准"的指标将在第一轮数据产出后确定。

### 0.5 红线（硬门槛）

即使总分达标，以下红线任一触发，系统不得判定为合格：

| 红线指标 | 门槛 | 严重程度 |
| --- | ---: | --- |
| A3 Bootstrap ARI | < 70 | 聚类结果不可标记为"稳定" |
| B1 Evidence Coverage | < 70 | 画像缺乏数据基础 |
| C5 M1 Fidelity | < 60 | 未学会深层动机，不是高质量模拟用户 |
| C6 Cluster Discrimination | < 60 | 模拟用户之间无法区分 |
| D1 Test-Retest ICC | < 0.70 | 评分不可靠 |

### A1-1：M1 Cohesion

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A1-1 |
| **指标名称** | M1 Cohesion（动机层类内一致性） |
| **定义** | 同一 cluster 内玩家在 M1（动机/诉求）维度上的平均语义相似度 |
| **所属维度** | A1 类内一致性 |
| **分值** | 1.5 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | `iceberg.M1` 标签向量（one-hot 或多热编码），或 `framework.needs` 的 primary/secondary 标签 |
| **数据粒度** | 玩家级（speaker_id 聚合后的 M1 标签分布） |
| **计算公式** | 对每个 cluster c：$$\text{Cohesion}_c^{M1} = \frac{2}{n_c(n_c-1)} \sum_{i<j} \text{sim}(x_i^{M1}, x_j^{M1})$$ 其中 sim 为余弦相似度（标签向量）或 Jaccard 相似度（标签集合）。整体加权：$$\text{M1Cohesion} = \sum_c \frac{n_c}{N} \cdot \text{Cohesion}_c^{M1}$$ |
| **聚合方式** | 按 cluster size 加权平均 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | M1 标签为 `unknown` 的玩家在计算该 cluster 的 M1 Cohesion 时排除；若 cluster 内 ≥ 50% 玩家 M1 缺失，该 cluster 的 M1 Cohesion 标记为 NaN，不计入加权平均 |
| **异常值处理** | 单玩家 cluster（n_c = 1）排除，Cohesion 无定义 |
| **阈值** | **待校准**。建议第一轮先建立 Baseline 分布，后续根据人工可接受聚类结果确定 |
| **统计置信区间** | Bootstrap 95% CI（重采样玩家 1000 次，计算 Cohesion 分布） |
| **输出JSON字段** | `A1.M1_cohesion.score`, `A1.M1_cohesion.ci_lower`, `A1.M1_cohesion.ci_upper`, `A1.M1_cohesion.per_cluster` |
| **失败诊断** | 若 M1 Cohesion < Baseline 中位数 − 1.5σ：M1 标签可能标注不一致，或 cluster 内玩家动机确实多样化 |
| **改进动作** | 1. 检查 M1 标签标注一致性；2. 检查该 cluster 是否需要拆分；3. 确认 M1 标签是否足够细粒度 |

### A1-6：Semantic Cohesion

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A1-6 |
| **指标名称** | Semantic Cohesion（语义向量类内一致性） |
| **定义** | 同一 cluster 内玩家的文本 embedding 平均余弦相似度 |
| **所属维度** | A1 类内一致性 |
| **分值** | 2.5 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | 玩家级 embedding 向量（从玩家所有语料片段的 embedding 取均值池化得到） |
| **数据粒度** | 玩家级（player embedding = mean pooling of segment embeddings） |
| **计算公式** | 对每个 cluster c：$$\text{Cohesion}_c^{sem} = \frac{1}{n_c} \sum_{i=1}^{n_c} \frac{\mathbf{e}_i \cdot \mathbf{e}_c}{\|\mathbf{e}_i\| \|\mathbf{e}_c\|}$$ 其中 e_c 为 cluster c 的质心向量（归一化均值）。整体加权：$$\text{SemanticCohesion} = \sum_c \frac{n_c}{N} \cdot \text{Cohesion}_c^{sem}$$ |
| **聚合方式** | 按 cluster size 加权平均 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 无 embedding 的玩家排除；若 cluster 内 ≥ 50% 玩家无 embedding，该 cluster 不计入 |
| **异常值处理** | 单玩家 cluster 排除；embedding 范数为零的向量排除 |
| **阈值** | **待校准**（注意：embedding 模型的 cosine 分布因模型而异，不能直接拍 0.8 作为"优秀"标准） |
| **统计置信区间** | Bootstrap 95% CI（重采样玩家 1000 次） |
| **输出JSON字段** | `A1.semantic_cohesion.score`, `A1.semantic_cohesion.ci_lower`, `A1.semantic_cohesion.ci_upper`, `A1.semantic_cohesion.per_cluster` |
| **失败诊断** | Semantic Cohesion 高但 M1–M5 Cohesion 低 → embedding 捕捉到了 M1–M5 之外的信息（如语言风格），cluster 可能按表达方式而非动机分组 |
| **改进动作** | 1. 检查 embedding 是否过度依赖语言风格而非语义内容；2. 确认 M1–M5 标签与 embedding 空间的一致性 |

### A2-1：M1 Separation

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A2-1 |
| **指标名称** | M1 Separation（动机层类间区分度） |
| **定义** | 不同 cluster 之间在 M1 维度上的区分程度，采用 Separation Ratio（类间距离/类内距离）以避免 embedding 尺度影响 |
| **所属维度** | A2 类间区分度 |
| **分值** | 1.5 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | `iceberg.M1` 标签分布向量（玩家级），与 A1-1 相同 |
| **数据粒度** | cluster 级 → 全局聚合 |
| **计算公式** | 对每对 cluster (i,j)：$$D_{between}^{M1}(i,j) = 1 - \text{sim}(\mathbf{c}_i^{M1}, \mathbf{c}_j^{M1})$$ 其中 c_i^{M1} 为 cluster i 的 M1 标签质心向量。$$D_{within}^{M1} = \frac{1}{K} \sum_c \frac{1}{n_c} \sum_{p \in c} (1 - \text{sim}(\mathbf{x}_p^{M1}, \mathbf{c}_c^{M1}))$$ $$\text{SeparationRatio}^{M1} = \frac{\text{mean}(D_{between})}{\text{mean}(D_{within}) + \epsilon}$$ 其中 ε = 1e-8 |
| **聚合方式** | 所有 pair 的 D_between 取均值；所有 cluster 的 D_within 取均值 |
| **0–100 转换** | SeparationRatio 理论上 ∈ [0, ∞)。归一化：$$\text{Score} = 100 \times \min\left(1, \frac{\text{SeparationRatio}}{\text{Baseline95th}}\right)$$ 其中 Baseline95th 为第一轮数据中 SeparationRatio 的 95 分位数。若尚未建立 Baseline，暂用 $$\text{Score} = 100 \times \frac{\text{SeparationRatio}}{1 + \text{SeparationRatio}}$$ |
| **缺失值处理** | 若某 cluster 的 M1 标签缺失率 > 50%，该 cluster 在此维度的 D_within 和所有涉及该 cluster 的 D_between 均标记为 NaN |
| **异常值处理** | D_within = 0（cluster 内所有玩家 M1 完全相同）→ 使用 ε 防止除零；此时 SeparationRatio 会极大，需标记为"需人工复核" |
| **阈值** | **待校准** |
| **统计置信区间** | Bootstrap 95% CI（重采样玩家后重新聚类 1000 次） |
| **输出JSON字段** | `A2.M1_separation.score`, `A2.M1_separation.ratio`, `A2.M1_separation.ci_lower`, `A2.M1_separation.ci_upper`, `A2.M1_separation.pairwise_matrix` |
| **失败诊断** | M1 Separation Ratio 低 → 不同 cluster 在动机层面趋同，cluster 可能未按动机区分 |
| **改进动作** | 1. 检查 M1 标签是否在聚类特征中权重不足；2. 确认聚类算法是否充分使用了 M1 信号；3. 检查是否存在动机趋同但行为分化的情况（M1 不应过度强制区分） |

### A3-1：Bootstrap ARI

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A3-1 |
| **指标名称** | Bootstrap ARI（Bootstrap 调整兰德指数） |
| **定义** | 以玩家为重采样单位，Bootstrap 50 次后，每次聚类结果与 Baseline 聚类结果的 ARI 均值。ARI 是调整随机机会后的聚类一致性指标，用于度量两次聚类标签的一致性。 |
| **所属维度** | A3 聚类稳定性 |
| **分值** | 4.0 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | 玩家级特征矩阵，Baseline 聚类标签（C_baseline），每次 Bootstrap 的聚类标签（C_k） |
| **数据粒度** | 玩家级 |
| **计算公式** | 1. 从 N 个玩家中随机抽取 80%（不放回），重复 50 次 2. 每次对子样本重新执行完整聚类流程（特征编码 → HDBSCAN） 3. 计算 ARI：$$\text{ARI}_k = \text{ARI}(C_{baseline}, C_k)$$ 其中 C_baseline 和 C_k 的标签需先通过匈牙利算法做最优匹配（cluster label 无固定编号） 4. 最终：$$\text{BootstrapARI} = \text{mean}(\text{ARI}_1, ..., \text{ARI}_{50})$$ |
| **聚合方式** | 均值（同时报告标准差） |
| **0–100 转换** | 原始值 ∈ [−1, 1]，实际 ARI ≥ 0。直接 ×100。负值截断为 0 |
| **缺失值处理** | 无聚类标签的玩家（HDBSCAN label = −1）在 Baseline 和每次 Bootstrap 中保留，但 ARI 计算时 noise 作为独立类别处理 |
| **异常值处理** | 若某次 Bootstrap ARI 偏离均值超过 3σ，标记为"不稳定性事件"并在报告中单独列出 |
| **阈值** | ≥ 90：优秀；80–89：良好；70–79：可接受；< 70：不通过（红线） |
| **统计置信区间** | Bootstrap 50 次 ARI 的 95% CI（百分位法） |
| **输出JSON字段** | `A3.bootstrap_ari.score`, `A3.bootstrap_ari.stdev`, `A3.bootstrap_ari.ci_lower`, `A3.bootstrap_ari.ci_upper`, `A3.bootstrap_ari.per_iteration`, `A3.bootstrap_ari.unstable_events` |
| **失败诊断** | ARI < 70：聚类结构对样本选择敏感，不够稳定。若 ARI 标准差 > 0.10：稳定性波动大，可能存在"边界玩家"导致聚类结果在两可之间切换 |
| **改进动作** | 1. 检查不稳定玩家是否集中在某几个 cluster 边界；2. 考虑增加 min_cluster_size 减少小簇；3. 若 HDBSCAN 不稳定，尝试调整 `cluster_selection_epsilon` 参数 |

### A3-2：Cluster Jaccard

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A3-2 |
| **指标名称** | Cluster Jaccard（簇 Jaccard 稳定性） |
| **定义** | 每次 Bootstrap 聚类与 Baseline 聚类之间，各 cluster 的 Jaccard 相似度均值 |
| **所属维度** | A3 聚类稳定性 |
| **分值** | 2.4 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | Baseline 聚类标签，每次 Bootstrap 聚类标签（经匈牙利算法匹配后） |
| **数据粒度** | cluster 级 → 全局聚合 |
| **计算公式** | 对每个 Baseline cluster c，在每次 Bootstrap k 中找到匹配的 cluster c'：$$\text{Jaccard}_{c,k} = \frac{|S_c \cap S_{c'}|}{|S_c \cup S_{c'}|}$$ 其中 S_c 为 Baseline 中 cluster c 的玩家集合，S_{c'} 为 Bootstrap 中匹配 cluster 的玩家集合。全局：$$\text{ClusterJaccard} = \frac{1}{50K} \sum_{k=1}^{50} \sum_{c=1}^{K} \text{Jaccard}_{c,k}$$ |
| **聚合方式** | 所有 cluster 和所有 Bootstrap 迭代的均值 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 若某 cluster 在 Bootstrap 中消失（无匹配 cluster），Jaccard = 0 |
| **异常值处理** | 同 A3-1 |
| **阈值** | **待校准**（建议与 ARI 联合解释：ARI 高 + Jaccard 高 = 全局 + 局部都稳定） |
| **统计置信区间** | 50 次 Bootstrap 的 per-cluster Jaccard 均值的 95% CI |
| **输出JSON字段** | `A3.cluster_jaccard.score`, `A3.cluster_jaccard.stdev`, `A3.cluster_jaccard.ci_lower`, `A3.cluster_jaccard.ci_upper`, `A3.cluster_jaccard.per_cluster` |
| **失败诊断** | 某 cluster Jaccard 持续低于 0.5 → 该 cluster 不稳定，可能依赖特定样本 |
| **改进动作** | 1. 检查不稳定 cluster 的样本量是否过小；2. 检查该 cluster 是否主要由 noise 点组成 |

### A4-3：Cluster Player Dominance

| 字段 | 内容 |
| --- | --- |
| **指标ID** | A4-3 |
| **指标名称** | Cluster Player Dominance（簇玩家垄断度） |
| **定义** | 检测某 cluster 是否主要由单个玩家的片段构成（"个人语言风格"冒充"群体画像"） |
| **所属维度** | A4 玩家级一致性 |
| **分值** | 1.75 |
| **指标类别** | 第一类：核心连续指标 |
| **输入字段** | 同 A4-1 |
| **数据粒度** | cluster 级 → 全局聚合 |
| **计算公式** | 对每个 cluster c：$$\text{Dominance}_c = \frac{\max_p n_{pc}}{n_c}$$ 其中 n_{pc} 为玩家 p 在 cluster c 中的片段数，n_c 为 cluster c 的总片段数。全局：$$\text{PlayerDominance} = 1 - \max_c \text{Dominance}_c$$ （最大垄断度越低 = 分数越高） |
| **聚合方式** | 取所有 cluster 中最大的 Dominance 值，取反 |

| **异常值处理** | 若某 cluster 的 Dominance ≥ 0.70，触发 **Player Dominance Warning**，该 cluster 在报告中标记为"单人特征风险" |
| **阈值** | ≥ 70% 触发警告。**待校准** |
| **统计置信区间** | 无需（取最大值） |

### B1：Evidence Coverage

| 字段 | 内容 |
| --- | --- |
| **指标ID** | B1 |
| **指标名称** | Evidence Coverage（证据覆盖率） |
| **定义** | 画像的所有 Atomic Claims 中，有直接访谈证据支持的比例，同时考虑证据来源的多样性 |
| **所属维度** | B 画像真实性 |
| **分值** | 7.0 |
| **指标类别** | 第二类：证据指标 |
| **输入字段** | 每个画像的 Atomic Claims 列表（每 claim 标注：支持证据的片段 ID 和 speaker_id 列表），访谈片段原文 |
| **数据粒度** | 画像级 → 全局聚合 |
| **计算公式** | **B1-1 Claim Coverage（70%权重）**：$$\text{Coverage} = \frac{|\{\text{claims} \mid \text{有} \geq 2 \text{条不同玩家证据}\}|}{|\{\text{全部 claims}\}|}$$ **B1-2 Evidence Diversity（30%权重）**：对每个有证据支持的 claim：$$\text{Diversity}_i = \frac{|\{\text{支持该 claim 的不同 speaker_id}\}|}{n_c}$$ 其中 n_c 为该画像对应 cluster 的玩家数。全局：$$\text{Diversity} = \text{mean}(\text{Diversity}_i)$$ **B1 = 0.70 × Coverage + 0.30 × Diversity** |
| **聚合方式** | 所有画像的加权均值 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 若某画像未拆分为 Atomic Claims（仍为自然语言段落），Coverage 和 Diversity 均无法计算，标记为"需先结构化" |
| **异常值处理** | 若某画像的 claim 数量 < 10，在报告中标注"命题数量不足" |
| **阈值** | **待校准**。红线：< 70 |
| **统计置信区间** | Bootstrap 95% CI（重采样 claims 1000 次） |
| **输出JSON字段** | `B1.evidence_coverage.score`, `B1.evidence_coverage.claim_coverage`, `B1.evidence_coverage.evidence_diversity`, `B1.evidence_coverage.ci_lower`, `B1.evidence_coverage.ci_upper`, `B1.evidence_coverage.per_persona` |
| **失败诊断** | Coverage 高但 Diversity 低 → 证据集中来自少数玩家，结论可能被个别玩家主导 |
| **改进动作** | 1. 对低 Diversity 的 claim，要求补充更多来源的证据；2. 若无法补充，降级为"部分玩家特征"而非"群体特征" |

### B3：Contradiction

| 字段 | 内容 |
| --- | --- |
| **指标ID** | B3 |
| **指标名称** | Contradiction（矛盾率） |
| **定义** | 画像核心 claim 中存在强反证的比例，并按 claim 重要性加权 |
| **所属维度** | B 画像真实性 |
| **分值** | 6.0 |
| **指标类别** | 第二类：证据指标 |
| **输入字段** | 每个 claim 的"支持证据列表"和"反对证据列表"，每个 claim 的重要性权重（核心/重要/辅助） |
| **数据粒度** | claim 级 → 画像级 → 全局聚合 |
| **计算公式** | **B3-1 Contradiction Rate（60%权重）**：$$\text{ContradictionRate} = \frac{|\{\text{claims} \mid \text{反对证据强度} \geq \text{支持证据强度}\}|}{|\{\text{全部 claims}\}|}$$ **B3-2 Weighted Contradiction（40%权重）**：$$\text{WeightedContradiction} = \frac{\sum_i w_i \cdot \mathbb{1}[\text{claim } i \text{ 有强反证}]}{\sum_i w_i}$$ 其中 w_i 为 claim 重要性权重：核心=3，重要=2，辅助=1。**B3 = 100 × (1 − [0.60 × ContradictionRate + 0.40 × WeightedContradiction])** |
| **聚合方式** | 加权平均 |
| **0–100 转换** | 如上公式（反向指标，取反后 ×100） |
| **缺失值处理** | 无反证搜索的 claim 排除（不计入分子和分母） |
| **异常值处理** | 若某核心 claim 被强反证，自动触发"画像修正建议" |
| **阈值** | **待校准**。建议 Contradiction Rate > 35% 时触发警告 |
| **统计置信区间** | Bootstrap 95% CI |
| **输出JSON字段** | `B3.contradiction.score`, `B3.contradiction.rate`, `B3.contradiction.weighted_rate`, `B3.contradiction.ci_lower`, `B3.contradiction.ci_upper`, `B3.contradiction.conflicting_claims` |
| **失败诊断** | 核心 claim 被反证 → 画像可能选择性引用了支持自己的证据，忽略了反面案例 |
| **改进动作** | 1. 对存在强反证的 claim，重新审视 claim 表述（加入限定条件）；2. 若反证来自 cluster 内显著少数派，考虑是否需要进一步拆分 cluster |

### B4：Profile Distinctiveness

| 字段 | 内容 |
| --- | --- |
| **指标ID** | B4 |
| **指标名称** | Profile Distinctiveness（画像区分度） |
| **定义** | 不同画像之间在核心命题上的差异程度，确保画像不是"改几个形容词的同一套描述" |
| **所属维度** | B 画像真实性 |
| **分值** | 6.0 |
| **指标类别** | 第二类：证据指标 |
| **输入字段** | 每个画像的 Atomic Claims 列表及其 embedding 向量 |
| **数据粒度** | 画像对（pairwise）→ 全局聚合 |
| **计算公式** | **B4-1 Unique Feature Rate（50%权重）**：对每个画像 c：$$\text{UFR}_c = \frac{|\{\text{claims} \mid \text{该 claim 在 cluster c 的 SupportRate 显著高于其他 cluster}\}|}{|\{\text{全部 claims}\}|}$$ 其中"显著高于"定义为 SupportRate_c − max(SupportRate_other) ≥ 0.2。全局：$$\text{UFR} = \text{mean}(\text{UFR}_c)$$ **B4-2 Pairwise Profile Similarity（50%权重）**：对每对画像 (i,j)：$$\text{Sim}_{ij} = \frac{|\{\text{claims in i} \mid \exists \text{ claim in j with cosine similarity} > 0.8\}|}{|\{\text{claims in i}\}|}$$ 全局：$$\text{ProfileSimilarity} = \frac{2}{K(K-1)} \sum_{i<j} \text{Sim}_{ij}$$ **B4 = 0.50 × UFR + 0.50 × (1 − ProfileSimilarity)** |
| **聚合方式** | 全局聚合 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 若某画像的 claims 未向量化，该画像对不计入 Pairwise Similarity |
| **异常值处理** | 若某对画像的 ProfileSimilarity > 0.7，标记为"画像趋同风险" |
| **阈值** | **待校准** |
| **统计置信区间** | Bootstrap 95% CI |
| **输出JSON字段** | `B4.distinctiveness.score`, `B4.distinctiveness.ufr`, `B4.distinctiveness.pairwise_similarity`, `B4.distinctiveness.ci_lower`, `B4.distinctiveness.ci_upper`, `B4.distinctiveness.overlapping_pairs` |
| **失败诊断** | UFR 低 + Pairwise Similarity 高 → 多个画像的核心命题高度重叠，画像之间缺乏真正差异 |
| **改进动作** | 1. 检查重叠的画像对是否应合并；2. 若不应合并，重新审视画像生成逻辑，确保每个画像突出其独特特征 |

| **数据粒度** | 单题 × 单画像 → 聚合 |

| **输出JSON字段** | `C1.M5_fidelity.score`, `C1.M5_fidelity.alignment`, `C1.M5_fidelity.recall`, `C1.M5_fidelity.contradiction`, `C1.M5_fidelity.specificity`, `C1.M5_fidelity.ci_lower`, `C1.M5_fidelity.ci_upper`, `C1.M5_fidelity.per_question`, `C1.M5_fidelity.per_persona` |

### C6：Cluster Discrimination

| 字段 | 内容 |
| --- | --- |
| **指标ID** | C6 |
| **指标名称** | Cluster Discrimination（群体区分度） |
| **定义** | 通过独立分类器判断不同画像的 AI 回答是否能被准确区分，从行为层面验证模拟用户是否产生了可识别的群体差异 |
| **所属维度** | C 模拟忠实度 |
| **分值** | 4.0 |
| **指标类别** | 第一类：核心连续指标（基于 LLM 回答的文本分类） |
| **输入字段** | 所有画像对所有题目的 AI 回答文本，各回答对应的真实 cluster 标签 |
| **数据粒度** | 回答级 → 全局聚合 |
| **计算公式** | 1. 收集所有画像对所有题目的回答，形成数据集 D = {(answer_text, cluster_label)} 2. 使用一个不看 cluster 名称的独立 classifier（LLM-based 或 embedding-based）预测每段回答来自哪个 cluster 3. 计算：$$\text{Macro-F1} = \frac{1}{K} \sum_{c=1}^{K} \text{F1}_c$$ $$\text{BalancedAccuracy} = \frac{1}{K} \sum_{c=1}^{K} \frac{\text{TP}_c}{n_c}$$ **C6 = 0.70 × Macro-F1 + 0.30 × BalancedAccuracy** |
| **聚合方式** | 所有题目的全局分类结果 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 若某 cluster 的回答数 < 5，该 cluster 在 Macro-F1 中权重降低（或排除），并在报告中标注 |
| **异常值处理** | 随机猜测基线 = 1/K × 100。若 Macro-F1 < 1/K+0.05，说明回答几乎无法区分 |
| **阈值** | **红线：< 60**。建议 60–70 为可接受，70–80 为良好，≥ 80 为优秀 |
| **统计置信区间** | Bootstrap 95% CI（重采样回答 1000 次） |
| **输出JSON字段** | `C6.cluster_discrimination.score`, `C6.cluster_discrimination.macro_f1`, `C6.cluster_discrimination.balanced_accuracy`, `C6.cluster_discrimination.ci_lower`, `C6.cluster_discrimination.ci_upper`, `C6.cluster_discrimination.confusion_matrix`, `C6.cluster_discrimination.chance_baseline` |
| **失败诊断** | Macro-F1 接近随机基线 → 不同画像的模拟回答在实际文本层面无法区分，即使 Judge 给每道题打高分，实际区分度仍然不足 |
| **改进动作** | 1. 检查混淆矩阵中哪些 cluster 之间最容易混淆；2. 加强这些 cluster 的 Prompt 区分度（注入更多特有特征）；3. 检查是否存在某些题目让所有 cluster 都给出类似回答（"万能答案"问题） |

### D1：Test-Retest

| 字段 | 内容 |
| --- | --- |
| **指标ID** | D1 |
| **指标名称** | Test-Retest Reliability（重测信度） |
| **定义** | 同一题目、同一画像在相同条件下重复生成回答时，评分的稳定性 |
| **所属维度** | D 评价可靠性 |
| **分值** | 4.0 |
| **指标类别** | 第三类：LLM Judge 指标 |
| **输入字段** | 随机抽取 30 题 × 若干画像，每组合重复生成 3 次回答（仅改变 random seed/temperature，保持 prompt/上下文/模型不变），每次回答的评分 |
| **数据粒度** | 单题 × 单画像 × 单次生成 → 聚合 |
| **计算公式** | **ICC(2,1)**：two-way random effects, absolute agreement, single measurement。$$\text{ICC} = \frac{MS_R - MS_E}{MS_R + (k-1)MS_E + \frac{k}{n}(MS_C - MS_E)}$$（其中 MS_R 为行间均方，MS_E 为误差均方，MS_C 为列间均方，k 为重复次数，n 为被试数）。**同时报告**：$$\text{MAD} = \frac{1}{N} \sum_{i=1}^{N} |\text{score}_{i,1} - \text{score}_{i,2}|$$（任意两次评分之间的平均绝对差） |
| **聚合方式** | 全局 ICC + MAD |
| **0–100 转换** | ICC ∈ [0,1]，直接 ×100。MAD 作为辅助指标，≤ 0.5 为良好 |
| **缺失值处理** | 3 次生成中任一次失败（如 API 超时），该样本排除 |
| **异常值处理** | 若某样本 3 次评分标准差 > 3× 全局标准差，标记为"异常波动样本" |
| **阈值** | ICC ≥ 90：优秀；80–89：良好；70–79：可接受；< 70：不合格（红线） |
| **统计置信区间** | ICC 的 95% CI |
| **输出JSON字段** | `D1.test_retest.icc`, `D1.test_retest.icc_ci_lower`, `D1.test_retest.icc_ci_upper`, `D1.test_retest.mad`, `D1.test_retest.score`, `D1.test_retest.unstable_samples` |
| **失败诊断** | ICC < 70 → 生成或评分过程存在显著随机性，评分结果不可靠。可能原因：LLM 生成随机性过高、Judge Prompt 不稳定、或题目本身含糊 |
| **改进动作** | 1. 降低生成 temperature；2. 检查 Judge Prompt 是否明确无歧义；3. 确认题目是否足够具体（过于开放的题目天然难以稳定评分） |

### D2：Judge Agreement

| 字段 | 内容 |

| **指标ID** | D2 |
| **指标名称** | Judge Agreement（评判者一致性） |
| **定义** | 多个 Judge 对同一答案评分的一致性。注意：Judge 间一致不等于与人工一致，此指标仅度量评判系统内部一致性 |

| **分值** | 2.0 |
| **指标类别** | 第三类：LLM Judge 指标 |
| **输入字段** | 同一批答案，在至少 3 种不同 Prompt 表述下的评分，以及（可选）在至少 2 种不同 Judge Model 下的评分 |
| **数据粒度** | 单答案 × 多 Prompt/Model → 聚合 |
| **计算公式** | **Prompt Robustness**：对每个答案，计算 3 种 Prompt 下评分的变异系数：$$CV_i = \frac{\sigma_i}{\mu_i}$$ 全局：$$\text{PromptRobustness} = 1 - \text{mean}(CV_i)$$ **Model Robustness**（可选）：计算不同 Model 下评分的最大差异：$$\text{ModelRange} = \max(\text{scores}_{model}) - \min(\text{scores}_{model})$$ **D4 = PromptRobustness（若有多 Model 则各占 50%）** |
| **聚合方式** | 全局聚合 |
| **0–100 转换** | 原始值 ∈ [0,1]，直接 ×100 |
| **缺失值处理** | 无 |
| **异常值处理** | 若 CV_i > 0.3，标记为"Prompt 敏感样本" |
| **阈值** | CV 均值 ≤ 0.15：优秀；0.15–0.25：良好；> 0.25：需关注。若 Model 间最大差异 > 1.0（1–5 分制），标记为"Model 敏感" |
| **统计置信区间** | Bootstrap 95% CI（重采样答案 1000 次） |
| **输出JSON字段** | `D4.judge_robustness.score`, `D4.judge_robustness.prompt_cv`, `D4.judge_robustness.model_range`, `D4.judge_robustness.ci_lower`, `D4.judge_robustness.ci_upper`, `D4.judge_robustness.prompt_sensitive_samples` |
| **失败诊断** | Prompt A=4.4, B=3.2, C=4.5 → CV 高，Judge 对 Prompt 措辞敏感。若 Model 间差异大 → Judge 对模型选择敏感，需固定 Judge Model |
| **改进动作** | 1. 选择评分最稳定的 Prompt 作为正式版本；2. 固定 Judge Model 不做切换；3. 在 Prompt 中增加更具体的评分锚点（如"3分=以下具体表现……"） |

---

### D 层汇总

| 指标 | 分值 | 主要方法 | 输出字段 |
| --- | ---: | --- | --- |
| D1 Test-Retest | 4.0 | ICC(2,1) + MAD | `D1.test_retest` |
| D2 Judge Agreement | 2.0 | ICC(2,k) / Krippendorff's α | `D2.judge_agreement` |
| D3 Human Agreement | 2.0 | ICC(2,1) + Spearman | `D3.human_agreement` |
| D4 Judge Robustness | 2.0 | CV + Score Range | `D4.judge_robustness` |
| **D 合计** | **10.0** | — | `D.score` |

## 五、总分计算

### 5.1 计算公式

```text
Total = A.score × 0.40 + B.score × 0.25 + C.score × 0.25 + D.score × 0.10
```

其中每层：

```text
A.score = A1 × 0.10 + A2 × 0.10 + A3 × 0.08 + A4 × 0.07 + A5 × 0.03 + A6 × 0.02
B.score = B1 × 0.07 + B2 × 0.06 + B3 × 0.06 + B4 × 0.06
C.score = C1 × 0.05 + C2 × 0.04 + C3 × 0.04 + C4 × 0.04 + C5 × 0.04 + C6 × 0.04
D.score = D1 × 0.04 + D2 × 0.02 + D3 × 0.02 + D4 × 0.02
```

### 5.2 红线检查

计算总分前，先检查以下红线。任一触发 → 总分标注为"不合格"：

```python
RED_LINES = {
    "A3.bootstrap_ari": 70,       # ARI < 70
    "B1.evidence_coverage": 70,   # 证据覆盖率 < 70
    "C5.M1_fidelity": 60,         # M1 动机忠实度 < 60
    "C6.cluster_discrimination": 60,  # 群体区分度 < 60
    "D1.icc": 70,                 # Test-Retest ICC < 0.70 → ×100 = 70
}
```

### 5.3 输出层级

```text
Level 1 — 总体能力：Total Score (0–100)
Level 2 — 能力结构：A/B/C/D 各层分数
Level 3 — 诊断报告：各子指标分数 + 薄弱环节自动诊断 + 改进建议
```

## 六、缺失值处理总则

| 场景 | 处理方式 |
| --- | --- |
| 标签为 `unknown` | 该样本在该维度排除，不计入分子和分母 |
| 标签缺失占比 > 50%（cluster 级） | 该 cluster 在该维度标记为 NaN，不计入该维度的加权平均 |
| 单样本 cluster | 类内指标（Cohesion 等）无定义，排除 |
| 生成失败（API 超时/错误） | 该样本排除，在报告中记录失败率 |
| Judge 评分失败 | 该样本排除，若失败率 > 5% 则触发警告 |
| 人工标注缺失 | 该样本排除，在报告中记录人工覆盖率 |

- 测试集

```text
Δ = V2_score − V1_score
```
