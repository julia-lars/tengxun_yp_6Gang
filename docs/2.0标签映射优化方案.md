## 2. 优化项详解

### 2.1 🚀 能力等级（最大提升点：12.4% → 80%+）

**问题**：`map_ability()` 只从 Profile statement 和 framework_agg 提取能力等级，完全忽略了 IMUR 792份问卷的 `metadata.gaming_background.skill_level`。

**数据现状**：
- IMUR 792份的 `metadata.gaming_background.skill_level` **全部有值**：
  - 顶尖水平，最高段位或排行榜: 88 (11.1%)
  - 水平较高，大多处于高段位: 279 (35.2%)
  - 水平中等偏上，大多处于中高段位: 266 (33.6%)
  - 水平一般，大多处于中低段位: 110 (13.9%)
  - 刚入门，还在熟悉基本操作: 7 (0.9%)
  - 说不清/不分段位: 42 (5.3%)

**优化方案**：
```python
# 新增函数：将 metadata.skill_level 映射到 ability 等级
SKILL_LEVEL_METADATA_TO_ABILITY = {
    "顶尖水平，最高段位或排行榜": "expert_competitive",
    "水平较高，大多处于高段位": "advanced",
    "水平中等偏上，大多处于中高段位": "intermediate",
    "水平一般，大多处于中低段位": "beginner",
    "刚入门，还在熟悉基本操作": "novice",
    # 以下无法确定，用 Profile statement 兜底
    "这款游戏不分段位，或不适合这样比较": None,
    "说不清": None,
}

def map_ability_from_metadata(metadata):
    """从 metadata.gaming_background.skill_level 推断能力等级"""
    gb = metadata.get("gaming_background", {})
    skill_level = gb.get("skill_level", "")
    if skill_level in SKILL_LEVEL_METADATA_TO_ABILITY:
        return SKILL_LEVEL_METADATA_TO_ABILITY[skill_level]
    return None
```

**优先级**：在 `map_ability()` 中，framework.ability.level → metadata.skill_level → Profile statement 的优先级链。

**预期提升**：12.4% → 80%+（792份IMUR全部有skill_level，加上Normal的Profile statement）

def infer_platform_from_games(games_list):
    """从游戏列表推断用户平台偏好"""

    for game in games_list:
        for key, plat in GAME_PLATFORM_MAP.items():

                platforms[plat] += 1
                break
    if not platforms:

### 2.3 游戏诉求（69.3% → 85%+）

**问题**：IMUR 792份有218份 motivation 为0，但这些 profile 的 `metadata.gaming_background` 包含丰富的游戏行为数据。

**优化方案**：

**A. 从 metadata 推断核心诉求**
- `peak_weekly_hours` = "21小时及以上" → 高投入玩家，暗示 `competitive_proof` / `ability_growth`
- `current_games` 中有大量竞技游戏 → 暗示 `competitive_proof`
- `experience_duration` = "9年以上" → 核心玩家，暗示 `ability_growth`

**B. 从 demographics 推断社交诉求**
- `occupation` = "学生" → 更可能 `social_belonging`
- `age` = "19—22岁" → 更可能 `social_belonging` / `competitive_proof`

**C. 从所有 Profile trait 做更广泛的语义匹配**
- 当前只匹配 `motivation` trait_type，可以扩展到 `need`、`preference` 等

**D. 从 segment 的原始内容推断（如果 _evidence_summary 不可用，直接从 labeled 文件读取）**

**被拒绝的方案**：
- ❌ **LLM分类**：对1059个profile做LLM调用成本高、不稳定，且关键词匹配已经够用（抽样50个仅3个未匹配）
- ❌ **重新生成profile**：工程量大，且IMUR数据本身是问卷，不是访谈，重新生成不会增加动机维度

**预期提升**：69.3% → 85%+

### 2.4 游戏风格（26.9% → 50%+）

**问题**：风格维度主要依赖 Profile 的 `combat_preference` 和 `social_preference` trait，IMUR 792份中只有55条 combat_preference 和91条 social_preference。

**优化方案**：

**A. 从 metadata 推断战斗风格**
- `skill_level` = "顶尖水平" + `peak_weekly_hours` = "21h+" → 更可能 `aggressive`
- `skill_level` = "刚入门" → 更可能 `passive`
- `current_games` 包含大量竞技射击 → 暗示 `aggressive`

**B. 从 demographics 推断社交风格**
- `age` = "19—22岁" + `occupation` = "学生" → 更可能 `friends`
- `age` = "31—35岁" + `occupation` = "企业员工" → 更可能 `solo`（时间碎片化）

**C. 从游戏名推断成长方式**
- 玩 RPG/MMO 类游戏 → 暗示 `progression`
- 玩竞技射击类 → 暗示 `skill`

**被拒绝的方案**：
- ❌ **LLM分类**：风格维度太主观，LLM推断也不可靠，且成本高
- ❌ **对所有未映射的默认填充**：会引入大量噪声

**预期提升**：26.9% → 50%+（主要是IMUR部分可以通过metadata推断）
