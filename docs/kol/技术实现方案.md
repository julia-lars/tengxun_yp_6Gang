## 一、架构总览

```
┌──────────────────────────────────────────────────────────────┐
│                      前端 (React + shadcn/ui)                  │
│  /kol  列表页  │  /kol/:id  画像详情  │  /kol/:id/chat  SSE对话  │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTP/SSE
┌──────────────────────────▼───────────────────────────────────┐
│                    后端 (Hono + Bun)                           │
│  GET /api/kol          KOL 列表                                │
│  GET /api/kol/:id      KOL 画像详情                             │
│  POST /api/kol/chat    对话 (SSE 流式)                          │
│    ├── System Prompt 组装 (Persona Card + Style Profile)       │
│    ├── RAG 检索 (pgvector 向量相似搜索)                         │
│    └── LLM 生成 (DeepSeek Chat, SSE 流式)                      │
└──────────────────────────┬───────────────────────────────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌──────────┐   ┌──────────────┐   ┌──────────────┐
   │PostgreSQL│   │ Python Embed │   │  DeepSeek API │
   │+pgvector │   │  Server :8765│   │  (chat only)  │
   │          │   │ bge-large-zh │   └──────────────┘
   │kol_      │   │   -v1.5      │
   │profiles  │   │ 1024-dim     │
   │+segments │   └──────────────┘
   └──────────┘
```

**为什么 Python + TypeScript 混合？**
- TypeScript (Bun + Hono)：Web 框架、API 路由、SSE 流式、前端
- Python (FastAPI + sentence-transformers)：embedding 模型推理。bge-large-zh-v1.5 是 HuggingFace 模型，Python 生态（sentence-transformers）是其最成熟的调用方式。JS/TS 侧的 transformers.js 需下载 ~300MB ONNX 运行时且安装不稳定，故选择 Python 微服务方案

## 三、数据库设计

### kol_profiles（KOL 画像）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | serial PK | — |
| name | text | UP 主名称 |
| bilibili_uid | text | B站 UID |
| persona_card | jsonb | LLM 提取的人设画像（身份/评价体系/内容领域/语气） |
| style_profile | jsonb | LLM 提取的风格画像（口头禅/语气/句长/表达习惯） |
| source_texts | text[] | 清洗后的全量语料文本 |

### kol_segments（语料片段）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | serial PK | — |
| kol_id | int FK → kol_profiles | 所属 UP 主 |
| bvid | text | B站视频 BV 号 |
| title | text | 视频标题 |
| original_text | text | 清洗后文本（~500 字/段） |
| source_url | text | B站视频链接 |
| embedding | vector(1024) | bge-large-zh-v1.5 向量（HNSW 索引） |
| ad_label | text | 广告分类：测评内容/广告口播/混合 |

## 四、画像提取方案

### 流程

```
清洗后语料 (~17万字)
    │
    ▼
DeepSeek Chat API (JSON mode)
    │  Prompt: 提取两份结构化画像
    │  ├── personaCard: identity, contentFocus, evaluationFramework, 
    │  │                platformPreference, specialty, toneSummary
    │  └── styleProfile: catchphrases, tone, avgSentenceLength,
    │                    firstPersonStyle, signaturePatterns
    ▼
kol_profiles.persona_card + style_profile (JSONB)
```

### 关键设计

- **区分"个人口头禅"和"B站通用套话"**：Prompt 中明确要求排除"大家好我是"、"投币点赞收藏"等所有 UP 主都说的套路，只保留该 UP 主独有的表达方式
- **失败兜底**：LLM 调用失败时自动降级为统计方法（褒贬词频分析 + 句长统计）
- **人工校验点**：用研专家需审核 LLM 提取的评价体系是否与该 UP 主真实风格一致

## 五、RAG 检索方案

### 架构

```
用户问题
    │
    ▼
Python Embed Server (FastAPI :8765)
  POST /embed  →  bge-large-zh-v1.5  →  1024-dim vector
    │
    ▼
pgvector HNSW 索引搜索
  SELECT * FROM kol_segments
  WHERE kol_id = $id
    AND ad_label != '广告口播'
  ORDER BY embedding <=> $query_vector
  LIMIT 3
    │
    ▼
3 条最相关语料片段 → 注入 System Prompt → LLM 生成回答
```

### 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| Embedding 模型 | bge-large-zh-v1.5 | 1024 维，HuggingFace 下载，ModelScope 镜像 |
| 向量索引 | HNSW | pgvector 默认，查询 <10ms |
| 相似度算法 | Cosine Distance (`<=>`) | pgvector 内置 |
| 检索数量 | Top-3 | 平衡上下文窗口与相关性 |
| 广告过滤 | `ad_label != '广告口播'` | 6 条纯广告片段排除 |

### 广告检测

- 关键词快筛（17 个广告品牌/术语词）
- ≥3 命中 → 广告口播（排除）
- 1-2 命中 → 混合（保留）
- 0 命中 + 文本 >100 字 → 测评内容（正常召回）

### 容错

- Embed 服务不可用 → 自动 fallback 到 ILIKE 模糊匹配
- pgvector 查询失败 → 同样 fallback

## 六、对话引擎

### System Prompt 结构

```
你是「{name}」，{identity}

## 你的身份
- 内容领域: {contentFocus}
- 平台偏好: {platformPreference}

## 你的评价体系
- 手感: {weight}
- 玩法: {weight}
- 画面: {weight}
- 叙事: {weight}

## 你的说话风格
- {speechHabits}

## 规则
1. 第一人称，口语化
2. 符合评价体系，不前后矛盾
3. 不懂就说不知道
4. 不使用 AI 话术
5. 有个性有态度

## 参考往期内容（RAG 检索结果）
{evidence_context}
```

### 流式输出

- 协议：SSE (Server-Sent Events)
- 框架：Hono `streamSSE()`
- 事件：`data: {token}` (逐字) → `data: {"type":"evidence","ids":[...]}` (溯源)
