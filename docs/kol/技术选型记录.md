## 决策 1：语言与运行时 — TypeScript (Bun) + 局部 Python

**结论**：主体 TypeScript (Bun + Hono)，embedding 推理侧用 Python (FastAPI + sentence-transformers)

**分析**：

| 方案 | 优点 | 缺点 | 判定 |
|------|------|------|:--:|
| 纯 TypeScript | 架构统一，部署简单 | embedding 模型（bge-large-zh）在 TS 生态无成熟调用方式。transformers.js 需 ONNX 运行时 ~300MB，安装不稳定，实测 `bun add` 超时 | ❌ |
| 纯 Python | embedding/聚类直接调用最成熟的库 | 需另起 Web 框架；团队以 TS 为主 | ❌ |
| **TS 主体 + Python embed 微服务** | 主体架构统一；embedding 用最成熟的 Python 库；Python 侧仅 50 行 FastAPI | 多一个进程要管理 | ✅ |

**实际实现**：
- TS 侧：Bun + Hono（Web 框架）+ Drizzle（ORM）+ React + shadcn/ui（前端）
- Python 侧：FastAPI（`:8765`）+ sentence-transformers（bge-large-zh-v1.5）
- TS 对话路由通过 `fetch("http://127.0.0.1:8765/embed", ...)` 调用 Python 服务

## 决策 2：LLM — DeepSeek Chat

**结论**：DeepSeek (`deepseek-chat`)

**分析**：

| 候选 | 优点 | 缺点 | 判定 |
|------|------|------|:--:|
| **DeepSeek** | API 兼容 OpenAI；中文能力强；价格低（¥1/百万 token）；JSON mode 支持好 | 不支持 embedding API | ✅ |
| GLM (智谱) | 支持 embedding API | 提供的 API key 已失效（401）；需要重新申请 | ❌ |
| MiniMax | 多模态 | 价格较高；本项目不需要多模态 | ❌ |

**实际使用**：
- 对话生成：`deepseek-chat`，SSE 流式，temperature=0.7，max_tokens=2048
- 画像提取：`deepseek-chat`，JSON mode，temperature=0.3
- 未使用 DeepSeek 做 embedding（不支持）

## 决策 3：Embedding 模型 — bge-large-zh-v1.5

**结论**：BAAI/bge-large-zh-v1.5（1024 维），通过 ModelScope 镜像下载，Python sentence-transformers 加载

**分析**：

| 候选 | 维度 | 中文效果 | 获取方式 | 判定 |
|------|:---:|:--:|------|:--:|
| **bge-large-zh-v1.5** | 1024 | ⭐⭐⭐ MTEB 中文榜首 | ModelScope 国内镜像（免翻墙） | ✅ |
| bge-small-zh-v1.5 | 384 | ⭐⭐ | 同上 | ❌ 维度不匹配 pgvector 列 |
| text-embedding-3-small | 1536 | ⭐⭐ | OpenAI API（需额外 key + 翻墙） | ❌ |
| TF-IDF (纯 JS) | 可变 | ⭐ 词匹配，无语义 | 零依赖 | ❌ 精度不够 |

**实际流程**：
1. `pip install modelscope` → `snapshot_download('BAAI/bge-large-zh-v1.5')` 下载到本地 (~1.2GB)
2. 存储侧：Python 批处理脚本读取 `kol_segments` → 逐条 encode → 写入 `embedding` 列
3. 查询侧：Python FastAPI 微服务 (`:8765`) → `POST /embed` → TS 路由 fetch 调用
4. pgvector `<=>` 余弦相似搜索，Top-3

## 决策 4：向量数据库 — pgvector (PostgreSQL 扩展)

**结论**：pgvector（复用现有 PostgreSQL，不加独立向量数据库）

**分析**：

| 候选 | 优点 | 缺点 | 判定 |
|------|------|------|:--:|
| **pgvector** | 与现有 PG 共用；零额外运维；Drizzle ORM 可管理；HNSW 索引查询 <10ms | 大规模（百万级）性能不如 Milvus | ✅ |
| Milvus | 十亿级向量性能最优 | 需独立部署；389 条数据杀鸡用牛刀 | ❌ |
| Chroma | 轻量，Python 原生 | 需另开服务；与现有 PG 架构不统一 | ❌ |

**实际实现**：
- 索引类型：HNSW（pgvector 默认）
- 查询：`ORDER BY embedding <=> $query_vector LIMIT 3`
- 与群体画像的 `source_segments` 表共享同一 PG 实例

## 决策 5：画像提取 — LLM 直接提取 vs 人工编写 vs 聚类

**结论**：LLM 直接提取（Persona Card + Style Profile），不依赖聚类

**分析**：

KOL 分身与群体画像的核心区别：KOL 是**个体级**（2 个人），群体画像是**群体级**（5-8 种类型）。

| 方案 | 适用场景 | KOL 适用性 |
|------|------|:--:|
| HDBSCAN 聚类 | 从大量样本中自动发现用户类型 | ❌ 只有 2 个人，无法聚类 |
| 人工编写 | 小规模，需要高度准确性 | 🟡 可行但效率低 |
| **LLM 直接提取** | 有大量文本语料，需要结构化画像 | ✅ |

**实际实现**：
- 将每位 UP 主清洗后的语料（~5-13 万字）送入 DeepSeek，JSON mode 输出
- 提取两份画像：`personaCard`（人设）+ `styleProfile`（风格）
- Prompt 约束：排除 B 站通用套话，只保留个人独有特征
- 失败兜底：LLM 不可用时降级为统计方法（褒贬词频 + 句长分析）

## 决策 6：RAG 检索 — 向量搜索 vs 关键词匹配

**结论**：pgvector 向量相似搜索 + ILIKE fallback

**分析**：

| 方案 | 召回质量 | 实现复杂度 | 判定 |
|------|:--:|:--:|:--:|
| ILIKE 模糊匹配 | ⭐ 词匹配，漏召回严重 | 低 | ❌ |
| **pgvector 向量搜索** | ⭐⭐⭐ 语义匹配 | 中（需 embed 服务） | ✅ |

**实际实现**：
- 主路径：用户问题 → Python embed → pgvector `<=>` 余弦相似 → Top-3
- 容错路径：embed 服务不可用 / pgvector 查询失败 → ILIKE fallback
- 质量控制：自动排除 `ad_label = '广告口播'` 的片段（6 条）

## 决策 7：广告检测 — LLM 分类 vs 关键词 vs 混合

**结论**：关键词快筛 + 边缘 case 不调 LLM（关键词准确度足够）

**分析**：

| 方案 | 准确度 | 成本 | 判定 |
|------|:--:|:--:|:--:|
| 纯 LLM 分类 | ⭐⭐⭐ | 389 次 API 调用 | 🟡 成本偏高 |
| 纯关键词 | ⭐⭐ | 零 | 🟡 边缘 case 可能误判 |
| **关键词为主** | ⭐⭐+ | 零 | ✅ 实测 6 条广告全部准确 |

**实际效果**：
- 17 个广告品牌/术语关键词
- 389 条中检出 6 条广告口播（手柄推广 ×3、云电脑 ×1、笔记本 ×1、外设 ×1）
- 无漏判（手工抽检确认）

## 决策 8：部署 — GHCR vs TCR vs 直建

**结论**：GHCR (GitHub Container Registry) — Git push 自动构建 → CVM pull 部署

**分析**：

| 方案 | 优点 | 缺点 | 判定 |
|------|------|------|:--:|
| **GHCR** | GitHub Actions 自带 `GITHUB_TOKEN`，零额外配置；与代码仓库同域 | 国内拉取需镜像 | ✅ |
| 腾讯云 TCR | 国内拉取快 | 需单独注册 + 配置凭据；学生项目无 TCR 权限 | ❌ |
| 服务器直建 | 最简单 | 构建吃 CPU/内存；无法回滚 | ❌ |

**实际实现**：
- `deploy.sh`：rsync 源码 → 服务器 `docker build` → `docker compose up -d`
- 公网地址：`http://49.232.59.125`
- 腾讯云镜像加速：`/etc/docker/daemon.json` → `mirror.ccs.tencentyun.com`
