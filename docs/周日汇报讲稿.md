# 周日汇报讲稿



## 【0:00–3:00】第一部分 · 团队介绍

各位老师、各位同学，大家好！我是 6Gang 团队的技术负责人朱丽烨，同时兼着用研的工作。我们团队来自北大元培学院，和腾讯 MUR 合作，做的是射击品类的 AI 模拟用户系统。今天由我代表团队汇报，一共三个部分：先介绍团队和工作方式，然后详细讲我在仓库里的开发工作，最后给项目做一个整体总结。

**（一）团队构成。** 我们一共六个人，采用"用研 + 开发"双线配置，而且每位同学都是跨角色工作：

- **类恺平**，产品经理兼用研专家——画像假设、标签体系、竞品研究，用研这条线的牵头人；
- **我自己**，技术负责人兼用研——整体架构、部署运维，还有数据与 KOL 语料方向；
- **张江宇**，测试负责人——设计了 A/B/C/D 四层评测体系、30 多项指标，750 题基线和线上复测都是他主导；
- **崔续衡**，后端开发——LLM SDK 封装、对话引擎、边界判定引擎；
- **林钰坤**，数据处理——14 个项目的访谈数据，清洗、打标、向量化全流水线；
- **闫瑾**，交互设计兼前端——标签选择器、虚拟访谈室、整体视觉规范。

**（二）工作形式，三个特点。**

第一，**用研和开发同频**。我们不是"用研做完交接给开发"——产品经理直接参与标注规范，测试同学自己写评测脚本，我作为技术负责人也做用研。每个人都能从用研的视角看代码，从代码的视角做研究。

第二，**文档驱动、仓库协作**。所有规范、方案、开发日志都放在同一个 GitHub 仓库里，从画像假设到 Embedding 规范全部可追溯；进展用 commit 和文档同步，由我统一把关合并。

第三，**数据闭环驱动迭代**。我们建立了"上线 → 评测 → 复测"的闭环：系统部署在腾讯云，评测结果全部数字化。本周刚完成一次全量线上复测，效果后面我会展开讲。

## 【3:00–7:30】第二部分 · 我的开发工作（约 1,150 字）

接下来详细讲我在这个仓库里的 commit。按时间线分三个阶段：**搭地基、跑数据、冲刺上线**。

**第一阶段：搭地基——把项目从零跑起来（7 月下旬）。**

先是项目初始化：搭起 monorepo 架构，把 pgvector 从源码编译安装到 PostgreSQL 16、建好 HNSW 索引，第一周 17 个测试全部通过。

然后是 KOL 数字孪生这条线：从数据库新表、API，到前端页面、SSE 流式对话，整条链路写了下来；语料侧做了 LLM 画像提取和套话清洗，389 条片段入库。

印象最深的一个 commit 是 **Embedding 选型**：先后试了 transformers.js、TF-IDF、HuggingFace 直连、ModelScope 镜像，最终落地 bge-large-zh-v1.5 加 Python FastAPI 微服务；同时把证据检索从 ILIKE 模糊匹配升级成 pgvector 余弦相似度——这一步决定了后面证据溯源的质量。

月底完成首次线上部署：腾讯云三容器，一键部署脚本，GitHub Actions 加 GHCR 自动构建。

**第二阶段：跑数据——群体画像流水线（8 月）。**

数据流水线 v2.0 完成：14 个项目、一万八千多条访谈片段，清洗后得到一万五千多条有效片段；AI 打标 v3.0——冰山模型五层加框架四维，共打标一万三千多条；bge-m3 向量化一万多条。

画像从 9 个聚类收敛到 5 个，也就是现在的 C1 到 C5，718 名受访者全部完成分配，支持多标签。配套的聚类方案研究、Embedding 规范也全部成文。

八月下旬做了一波体验打磨：证据卡片、可信度面板、历史对话无限滚动、雷达图、相似画像、KOL 置信度。还有一个很有意思的 commit——**口语化 prompt**：禁止 AI 用 Markdown、括号动作、分点回答，让它的回答更像真人。

**第三阶段：冲刺上线——汇报前的质量攻坚（9 月）。**

边界引擎：重构了职责划分，修复"产品设计、营销类问题被误判为无关问题"的 bug——这直接影响误拒答率，后来线上复测误拒答 0 例，基础就是在这里打下的。

证据链：KOL 语料切成 200 字以内的语义片段，证据匹配引入 LLM 预评分，让回答的"出处"更精准。

汇报前这一周的 commit，重点讲四个：

1. 修复部署链路的三个阻塞项，恢复部署构建；
2. nginx 代理超时从 60 秒调到 300 秒，修复长对话被 504 掐断的问题；
3. **KOL 语料收尾**：320 个视频全量采集，其中 128 个完成转写和切分，约 31 万字、2,871 条片段，线上已全部更新；
4. **线上复测结果入文档**：610 题综合 4.25 分，深度从 2.93 提升到 3.83，误拒答 0 例。

到这两天，我还在做运维收尾——修了部署脚本卡死和容器健康检查的问题。

**一句话总结我的 commit 主线**：从架构搭建，到数据生产化，再到上线前的质量冲刺——既是架构师，也是救火队员。

## 【7:30–9:30】第三部分 · 项目总结（约 520 字）

最后给项目做一个总结。

**项目是什么？** 一句话：把 14 个项目的玩家访谈数据，变成一个可以对话、可以溯源的虚拟玩家群；再加上 B 站 UP 主的数字孪生。用研同学在系统里选标签，就能匹配到对应的群体画像，像跟真人深访一样提问，AI 用画像的人设回答，每一句都能溯源到原始语料。

**做到了什么程度？** 五个数字：

- **数据**：15,395 条有效片段，冰山五层打标，向量化入库；
- **画像**：5 个群体画像，718 名受访者全部分配；
- **KOL**：320 个视频采集，128 个完成转写，2,871 条语义片段已上线；
- **质量**：四层评测体系，线上复测 610 题综合 4.25 分，深度短板从 2.93 提升到 3.83，误拒答 0 例；
- **交付**：部署在腾讯云，随时可以线上演示。

**下一步**：深度作答仍是优化重点，虽然已经从 2.93 提到 3.83；群体画像侧的证据检索要升级成向量检索，和 KOL 侧对齐；另外还有 192 个视频的语料可以继续转写扩充。

**收尾**：六个人、八个星期，我们交付了一个能演示、能评测、能在线上稳定运行的 AI 模拟用户系统。我的汇报到这里，接下来进入线上演示环节。谢谢大家！
