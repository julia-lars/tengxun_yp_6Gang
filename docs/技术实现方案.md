## 三、数据库设计

### 核心表关系

**群体画像**：`source_segments` (1)→(N) `personas` → `chat_sessions`

**KOL 分身**：`kol_profiles` (1)→(N) `kol_segments`

**受访者**：`respondents` 通过 `(source_file, speaker_id)` 关联 `source_segments`

### 关键表结构

**source_segments**（AI 标注后的用户原声片段）：
- `original_text` / `cleaned_text`：原始文本与清洗后文本分离，COALESCE 查询
- `speaker_id` / `speaker_role`：区分被访者/主持人
- `preceding_question`：保留主持人的提问语境
- `annotation` (jsonb)：冰山五层 + 框架四维度标注结果
- `embedding` (vector(1024))：pgvector 向量，HNSW 索引
- `persona_ids` (integer[])：关联的画像 ID 数组

**kol_profiles**（KOL 画像）：
- `persona_card` (jsonb)：身份定位/内容领域/评价体系/平台偏好
- `style_profile` (jsonb)：说话风格/语气倾向/speechHabits
- `source_texts` (text[])：所有清洗后的语料文本

**kol_segments**（KOL 语料片段）：
- 按 500 字分片，关联 `kol_profiles`
- `embedding` (vector(1024))：向量检索用
- `source_url`：B站视频链接

## 四、模型选型

| 环节 | 选型 | 替代方案 | 选型理由 |
|------|------|----------|----------|
| LLM 对话 | DeepSeek-Chat | GLM-4-Flash / MiniMax | 成本低、中文好、支持流式 |
| LLM Embedding | text-embedding-3-small | bge-large-zh-v1.5 | DeepSeek 自带，免部署 |
| 语音转文字 | faster-whisper medium | large-v2 / 商用 ASR | 免费、GPU 加速、中文可接受 |
| 标点恢复 | DeepSeek-Chat | 专用标点模型 | 复用已有 API，质量好 |
| 聚类算法 | HDBSCAN | K-Means / DBSCAN | 自动选簇数，容忍噪声点 |
| 降维可视化 | UMAP | t-SNE | 保留全局结构，速度快 |

## 五、RAG 检索方案

**当前方案**：ILIKE 模糊匹配（`WHERE original_text ILIKE '%keyword%'`）

**目标方案**：pgvector 向量相似搜索

```
用户提问 → embed(question) → 1024维向量
  → SELECT * FROM segments
     ORDER BY embedding <=> query_vector
     LIMIT 5
  → 检索到的原文片段 → 注入 System Prompt → LLM 生成回答
```

**关键参数**：
- 向量维度：1024
- 索引类型：HNSW (m=16, ef_construction=64)
- 检索数量：Top-5，按相似度排序
- 长文本策略：500 字切片，overlap 100 字

### 7.4 KOL 画像提取方案

```
清洗后语料 (~17万字)
    │
    ▼
DeepSeek Chat API (JSON mode)
    │  Prompt: 提取两份结构化画像
    │  ├── personaCard: identity, contentFocus, evaluationFramework,
    │  │                platformPreference, specialty, toneSummary
    │  └── styleProfile: catchphrases, tone, avgSentenceLength,
    │                    firstPersonStyle, signaturePatterns
    ▼
kol_profiles.persona_card + style_profile (JSONB)
```

**关键设计**：
- **区分"个人口头禅"和"B站通用套话"**：Prompt 中明确要求排除"大家好我是"、"投币点赞收藏"等所有 UP 主都说的套路，只保留该 UP 主独有的表达方式
- **失败兜底**：LLM 调用失败时自动降级为统计方法（褒贬词频分析 + 句长统计）
- **人工校验点**：用研专家需审核 LLM 提取的评价体系是否与该 UP 主真实风格一致

### 7.5 KOL RAG 检索方案

```
用户问题
    │
    ▼
Python Embed Server (FastAPI :8765)
  POST /embed  →  bge-large-zh-v1.5  →  1024-dim vector
    │
    ▼
pgvector HNSW 索引搜索
  SELECT * FROM kol_segments
  WHERE kol_id = $id
    AND ad_label != '广告口播'
  ORDER BY embedding <=> $query_vector
  LIMIT 3
    │
    ▼
3 条最相关语料片段 → 注入 System Prompt → LLM 生成回答
```

**关键参数：**

| 参数 | 值 | 说明 |
|------|-----|------|
| Embedding 模型 | bge-large-zh-v1.5 | 1024 维，ModelScope 镜像下载 |
| 向量索引 | HNSW | pgvector 默认，查询 <10ms |
| 相似度算法 | Cosine Distance (`<=>`) | pgvector 内置 |
| 检索数量 | Top-3 | 平衡上下文窗口与相关性 |
| 广告过滤 | `ad_label != '广告口播'` | 6 条纯广告片段排除 |

**广告检测**：17 个广告品牌/术语关键词快筛。≥3 命中 → 广告口播（排除）；1-2 命中 → 混合（保留）；0 命中 + 文本 >100 字 → 测评内容（正常召回）。

**容错**：Embed 服务不可用 → 自动 fallback 到 ILIKE 模糊匹配。

### 7.6 KOL 对话引擎

**System Prompt 结构：**

```
你是「{name}」，{identity}

## 你的身份
- 内容领域: {contentFocus}
- 平台偏好: {platformPreference}

## 你的评价体系
- 手感: {weight}
- 玩法: {weight}
- 画面: {weight}
- 叙事: {weight}

## 你的说话风格
- {speechHabits}

## 规则
1. 第一人称，口语化
2. 符合评价体系，不前后矛盾
3. 不懂就说不知道
```
