## 1. 设计目标

### 1.1 最终用途优先级

```
AI 虚拟用户 / AI 访谈  >  用户画像 / Persona  >  标签检索  >  评测体系
     (第一优先)              (第二优先)          (第三优先)     (第四优先)
```

所有提取标准以"AI 虚拟用户能生成有证据支撑、可追溯来源的回答"为第一目标。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **原文不可变** | `original_text` 提取后永不修改，用于回溯和重跑 |
| **可追溯** | 每条 Segment 保留完整上下文，可回溯到原始文件 |
| **身份 ≠ 行为** | 用户的年龄、职业、游戏列表等是档案属性，独立于 Segment 存储 |
| **先归属再提取** | 座谈会必须先确认每句话是谁说的，再提取信息 |
| **提问语境完整** | preceding_question 必须包含完整的提问链，不能丢失上下文 |

### 1.3 数据层级关系

```
                    原始访谈文件 (docx / xlsx)
                           │
                ┌──────────┴──────────┐
                ▼                     ▼
         一对一访谈               座谈会（多人）
                │                     │
                │             ① 说话人归属
                │             ② 参与者档案提取
                │                     │
                └──────────┬──────────┘
                           ▼
                       Segment
                 （一个受访者一次连续发言）
                           │
                           ▼
                    参与者档案 (Profile + Gaming Background)
                 （从自我介绍段中提取的客观属性）
```

## 2. 数据模型

### 2.1 两层结构

本文档定义两层数据，每层有明确的职责边界：

```
Layer 0：参与者档案（Participant）
         ├── 基础用户属性（Profile）：年龄、职业、地区……
         └── 游戏背景（Gaming Background）：当前游戏、平台、经历……

Layer 1：片段（Segment）
         一个受访者一次连续发言的完整原文，包含：
         ├── original_text：原始发言文本
         ├── preceding_question：触发该发言的完整提问链
         ├── speaker_id：说话人标识
         └── source_file：来源文件
```

### 2.2 参与者档案（Participant）

**定义**：从自我介绍或访谈中提取的、描述"这个用户是谁"的客观属性信息。

**职责**：
- 为后续用户聚类提供基础特征
- 与 Segment 分离，避免把"年龄 27 岁"和游戏行为混为同类数据

**子结构**：

| 子层 | 包含内容 | 示例 |
|------|------|------|
| **基础用户属性** | 年龄、性别、职业、教育、地区 | 27 岁，工程师，深圳 |
| **游戏背景** | 当前游戏、平台、经历、频率、时长 | 玩 Valorant 3 年，PC，每天 2 小时 |

### 2.3 Segment（片段）

**定义**：一名受访者在一次连续发言中表达的一个相对完整语义块。

**职责**：
- 保留完整语境和上下文
- 作为 AI 虚拟用户回答时的证据来源
- 作为 Segment Embedding 的嵌入对象

**边界规则**：
- 同一受访者连续发言，如果语义主题明显切换，应拆分
- 主持人提问不单独成 Segment，但 `preceding_question` 保留语境
- 同一受访者跨多行回应同一主题时，合并为一个 Segment

## 3. 访谈类型与提取流程

### 3.1 两种访谈类型

| 类型 | 特征 | 典型文件 |
|------|------|------|
| **一对一访谈** | 一名主持人 + 一名受访者，交替发言 | 绝大多数 docx 文件 |
| **座谈会（Focus Group）** | 一名主持人 + 多名受访者，用户之间可能互相回应 | 部分 docx 文件 |

### 3.2 一对一访谈流程

```
原始文件
   │
   ▼
识别 Moderator / Interviewee 发言交替模式
   │
   ▼
标记 speaker_role
   │
   ▼
切分 Segment（只保留 interviewee 发言）
   │
   ▼
提取参与者档案（从自我介绍段）
```

### 3.3 座谈会流程

```
原始文件
   │
   ▼
① 说话人归属（Speaker Attribution）
   把每段话归属到具体的人：Moderator / P001 / P002 / P003 …
   │
   ▼
② 参与者档案提取
   从自我介绍中提取每位参与者的 Profile + Gaming Background
   │
   ▼
③ 用户发言切分
   按说话人 + 语义主题切分 Segment
   │
   ▼
④ preceding_question 提取
   按 §6.7 规则，为每个 Segment 提取完整提问语境
```

> **关键原则**：座谈会绝不能先把整段对话直接丢给 Segment 切分。必须先完成说话人归属，否则会出现 P001 的观点被错误归属到 P002。

## 4. 说话人归属

### 4.1 适用场景

座谈会文件（多人参与）必须执行此步骤。一对一访谈可跳过（发言者天然唯一）。

### 4.2 归属规则

| 规则 | 说明 |
|------|------|
| **每人一个唯一 ID** | 同一文件内，每个参与者分配唯一 `speaker_id`（P001 / P002 / P003 …） |
| **主持人单独标记** | 主持人标记为 `speaker_role = "moderator"`，不参与 Segment 提取 |
| **ID 全程一致** | 同一参与者在文件内的所有发言使用同一个 `speaker_id` |
| **无法确认说话人** | 标记为 `speaker_id = "unknown"`，不进入 Segment 提取，但保留原文 |
| **多人同时发言** | 同上，标记为 `speaker_id = "unknown"`，不提取 |

### 4.3 归属示例

```
原文：
Moderator: "你们通常和谁一起玩？"
P001: "I usually play with my friends..."
P002: "I mostly play solo..."
P003: "Depends on the game..."

归属结果：
Moderator → preceding_question for P001, P002, P003
P001 → Segment (speaker_id="P001", speaker_role="interviewee")
P002 → Segment (speaker_id="P002", speaker_role="interviewee")
P003 → Segment (speaker_id="P003", speaker_role="interviewee")
```

## 5. 参与者档案提取标准

### 5.1 提取原则

> **不要因为信息出现在"自我介绍"里，就认为它一定是档案。**

一段自我介绍可能同时包含：档案信息、游戏背景、行为习惯。必须拆分到不同层级。

### 5.2 提取示例

```
原文："Hi, my name is Alex M. I'm 27 and I'm currently playing Valorant.
       I've been playing every night for about two hours for the last three years."
```

**拆分结果**：

```
┌── Profile（基础用户属性）
│   name: Alex M.
│   age: 27
│
├── Gaming Background（游戏背景）
│   current_games: [Valorant]
│   experience_years: 3
│   daily_play_hours: 2
│
└── Segment（原始发言保留，供后续分析）
    original_text: "I've been playing every night for about two hours..."
```

### 5.3 档案分类规则

| 如果原文说的是…… | 归类为…… | 原因 |
|------|------|------|
| 年龄、性别、职业、教育、地区 | **Profile** | 客观身份属性 |
| 当前玩的游戏列表 | **Gaming Background** | 游戏背景，不是态度 |
| 玩了多久、什么平台 | **Gaming Background** | 经历/平台信息 |
| 每天玩多久、什么频率 | **Gaming Background** | 行为习惯，归入档案 |
| 为什么喜欢某个游戏 | **Segment** | 态度/动机，保留在 Segment 中 |
| 什么情况下会停止玩 | **Segment** | 条件反应，保留在 Segment 中 |
| 跟谁一起玩、怎么玩 | **Segment** | 行为模式，保留在 Segment 中 |

### 5.4 档案字段规范

```json
{
  "participant_id": "P001",
  "source_file": "研究项目/座谈会文件名.docx",
  "profile": {
    "name": "Alex M.",
    "age": 27,
    "occupation": "工程师",
    "location": "深圳"
  },
  "gaming_background": {
    "current_games": ["Valorant", "COD"],
    "platform": ["PC"],
    "experience_years": 5,
    "genre_experience": ["FPS", "战术竞技"]
  }
}
```

| **合计** | **68** | | |

### 6.2 一对一访谈：docx 提取规范

1. 用 python-docx 提取所有段落和表格
2. 大多数 docx 文件以表格形式存储（两列：主持人 | 受访者），部分可能是段落形式
3. 识别 Moderator 和被访者发言交替模式
4. 标记 `speaker_role`（interviewee / moderator）
5. 对每条被访者发言，按 §6.7 规则提取 `preceding_question`
6. **最终落盘只保留被访者发言**（moderator 语境通过 `preceding_question` 保留）
7. 同一被访者连续发言如主题切换明显，应拆分为多个 Segment

### 6.3 座谈会：docx 提取规范

在 §6.2 的基础上，额外执行：

1. **先做说话人归属**（§4），为每个参与者分配唯一 `speaker_id`
2. **从自我介绍段中提取参与者档案**（§5），该段也纳入 Segment 提取
3. 参与者之间的互相回应保留在 `preceding_question` 中（标注是哪个参与者说的）
4. 多人同时发言、无法确认说话人的段落 → `speaker_id = "unknown"`，不进入 Segment 提取

### 6.4 记录表（xlsx）提取规范

> **适用**：枪战类长线新手体验研究 `用户记录表.xlsx`、生存撤离类新手引导体验研究 `整合记录表.xlsx`。
> 这两份文件不是对话，也不是一问一答矩阵，而是研究员整理的**工作底稿**，需先按 Sheet 判类再决定动作。

#### 6.4.1 四类 Sheet 判定

| 类别 | 判定依据 | 内容性质 | 处理 |
|------|---------|---------|------|
| ① 档案/样本 | 列头是字段名（Name/Age…） | 受访者名册、组别定义 | → `respondents` |
| ② 大纲 | 列头是 Question/Remark，无回答 | 提问脚本 | 只做问题参考 |
| ③ 访谈回答矩阵 | 列头是人，格=受访者回答 | 行=问题、列=受访者 | → Segment |
| ④ 行为观察/结论 | 列头是人但格=研究者转述/结论 | 观察笔记、对比、结论 | 不产 Segment |

**关键**：③ 与 ④ 的差别看**单元格主体是谁**——③ 是受访者原话（第一人称"我…"），④ 是研究者转述（`【洞察】【行为】`、`引导设计特点` 等）。

#### 6.4.2 各类处理规则

**① 档案类 → `respondents`**

- `用户列表`：`Name→profile.name`、`Age→profile.age`、`Gender→profile.gender`、`Ethnicity→profile.ethnicity`、`Platform→gaming_background.platform`、`GROUP SEGMENT→group_code`、游戏经验 checklist（`x` 标记）→ `gaming_background.current_games`。
- `样本条件`：组别定义（如 G1 无经验 / G3 经验）仅作 `group_code` 校验，不落库。

**② 大纲类**：提取问题文本作 `preceding_question` 参照，不产出数据。

**③ 访谈回答矩阵**：按 6.4.3 转置成 Segment。

**④ 行为观察/结论类**：默认不产出 Segment（非受访者原话，混入会污染虚拟用户语料）。

#### 6.4.3 访谈回答矩阵转置规则（仅 ③）

```
1. 列头 → 受访者：解析 speaker_id + group_code + display_name
2. 行头 → 问题：合并「章节(A列) + 问题(B列)」成 preceding_question
3. 剔除非问题行：章节标题（一、二、三…）、【引导语】、【任务N】、
   「观察：」行、模块标题行（测试前访谈 / 游戏体验 / 第一局…）
4. 每个非空单元格 → 1 条 Segment：
     original_text       = 单元格文本（原样保留，不做清洗）
     preceding_question  = 该行问题
     speaker_id          = 该列受访者
5. 同一 workbook 不同 Sheet 若为不同一批人 → 分开存为独立 source_file
```

**行头拼接示例**：

| Sheet | 行头位置 | 拼接结果 |
|------|---------|---------|
| 【一期】暗区 | A 列即问题 | `"1.1<暗区突围经验> 时长、接触、频率、段位、水平"` |
| 【二期】塔科夫 | A=模块、B=问题 | `"仓库介绍：仓库的物资丰富度、分类、排列方式"` |

#### 6.4.4 逐文件 Sheet 分类表

### 6.5 关键注意事项

- 搜打撤品类研究/海外有 8 组中英文对照文件，优先用中文版，英文原版留作对照
- 漫威争锋的"文字转录"文件可能不是对话体，需单独处理
- 美国 HD 端用户生态研究的 4 个文件已按用户类型分好（放松/竞技/社交/叙事），标签保留在 `source_file` 字段中
- 输出全部用 UTF-8 编码
- `speaker_id` 只保证同一 `source_file` 内唯一，不跨文件关联
- 组别代号带不确定标记（如 `G3?`）原样保留，不抹平

### 6.7 preceding_question 提取规则

**核心原则**：`preceding_question` 记录触发该回答的提问语境。找到正确的问题即可，大多数情况下不需要叠加前置问题链。

#### 6.7.1 提取规则

**默认规则**：`preceding_question` = 直接触发该回答的那个问题。

**例外规则（极少使用）**：只有在同一话题下、对上一回答进行**真正追问**时，才在追问回答的 pq 上加上前置问题：

```
preceding_question = "前置问题 → 当前问题"
```

**判定"真正追问"的标准**：
- 同一话题：当前提问与上一提问围绕同一子话题，未切换讨论方向
- 真正追问：当前提问是对上一回答的跟进或深挖，离开上一回答的语境无法独立理解

**关键约束**：此类情况非常少，不要每句都加前置问题。大部分回答的 pq 只包含直接提问即可。

#### 6.7.2 提取示例

**默认规则 — 直接提问即可**：

```
M: "你一般下班后玩什么游戏？"
U: "我主要玩COD。"
M: "跟谁一起玩？"
U: "跟朋友一起。"
```

**座谈会场景**：

```

```

#### 6.7.3 特殊情况

| 情况 | 处理方式 |
|------|------|
| 文件开头尚无提问 | 回溯到第一句有实质内容的主持人发言 |
| 主持人发言被截断在两行 | 合并为一条完整发言后再确定 |
| 同一行多位受访者回应同一提问 | 共用同一个 preceding_question |
| 受访者互相回应（非主持人提问） | 标注 `[P001 说：…]` |
