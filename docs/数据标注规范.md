## 1 标注框架总览

### 1.1 标注目标

标注不是把每句话"塞满标签"，而是忠实记录：

1. 玩家明确说了什么。
2. 可以在什么证据强度下推断什么。
3. 哪些信息未知、矛盾或受场景限制。
4. 该片段的证据如何支持不同 M 层标签，以及这些标签之间是否存在显式因果/支持关系。

最终标签必须同时满足：

- **可追溯**：每个结论能回到原始文件、片段和证据文本。
- **可复核**：不同标注者依据同一规则可得到相近结果。
- **可计算**：字段和值域稳定，能用于聚类、筛选和评测。
- **不过度推断**：没有证据时输出空标签，不凭常识补齐人设。

### 1.2 双层标注体系

每条访谈片段需要完成两层标注：

| 冰山五层（Iceberg） | 框架七维（Framework） |
|:--|:--|
| M1 动机/诉求 | 诉求（Needs） |
| M2 期待/标准 | 能力（Ability） |
| M3 认知/观点 | 风格（Style） |
| M4 感受/情绪 | 平台（Platform） |
| M5 行为/应对 | 模式（Mode） |
| | 资产（Assets）← 扩展 |
| | 甜区（Sweet Spot）← 扩展 |

冰山五层是纵向的"为什么→怎么做"因果链；框架七维是横向的"这个人是什么样的"特征画像。同一条片段可能同时触发两层标注，也可能只触发其中一层。

### 1.3 标注粒度原则

| 原则 | 说明 |
|:--|:--|
| 一碎片一标注 | 每条片段独立标注，不依赖同一说话人的其他片段。 |
| 原文为准 | 标注基于片段中明确表达的内容，不做推断跳级。 |
| 宁缺毋滥 | 无法确定层次/维度时标注为空，不强行归类。 |
| 多标签允许 | 同一层次允许多个标签值，但每个标签必须有独立证据。 |
| 上下文保留 | 标注时需参考 `preceding_question` 字段，理解说话人是在回答什么问题。 |

### 1.4 标注单元

基本单元为"一名玩家在同一问题语境下表达一个相对完整意思的片段"。

- 同一段包含多个独立观点时，应拆分。
- 必须依赖主持人问题才能理解时，应保留最短必要问题上下文。
- 相邻短句共同构成因果链时可合并。
- 不把不同玩家的发言合并。
- 中英文对照材料优先标中文版，英文原文作为复核证据。

### 1.5 不标注内容

- 主持人的纯引导、确认、寒暄。
- 无法识别说话人的多人混合陈述。
- 只有"嗯""对""不知道"等、离开上下文没有意义的片段。
- 纯产品事实、没有玩家态度或行为的信息。
- 重复转录或中英文同义副本。

## 2 数据标注决策机制

### 2.1 核心原则

> **复杂标签体系原则**
>
> 本项目不以"减少标签数量"为目标。允许建立多层级、大规模、多标签、跨维度、关系型、语义推断型标签体系。
>
> **但：标签体系可以复杂，单个标签的进入条件必须明确。**
>
> 标注不是对每段话做孤立分类，而是在单条 Segment 内尽可能恢复 **"行为→情绪→认知→期待→动机"** 的因果链。链条允许断裂：某层没有证据时该层输出空数组，**禁止为填满五层而编造标签**。

### 2.2 证据直接性优先原则

M 层之间不存在强制的生成顺序。标注时应优先寻找**距离证据最近、映射最唯一**的标签，而不是从 M5 逐层推导到 M1。

```text
直接证据
    ↓
语义归纳
    ↓
局部因果推断
    ↓
跨层推断
```

**核心规则：**

- **允许跨层推断**：M5 证据可以直接支持 M1，只要 M1 自身满足其证据门槛和 confidence threshold。
- **禁止为了填充链条而制造中间层**：不能因为“想推出 M1”而强行生成没有独立证据的 M4/M3/M2。
- **推断依赖的是证据强度，不是层级顺序**：每个标签必须独立通过自身的证据门、推断规则门和 confidence 门。

**示例：**

> “我打排位主要是为了上分，因为赢了以后段位会涨。”

- M1 = `competitive_proof`：直接证据，“为了上分”“段位会涨”。
- M5 = `ranked_grind`：直接证据，“打排位”。

此处不需要先生成 M4、M3、M2 才能标注 M1。两个标签分别来自不同证据，独立判断。

### 2.3 四种标签状态

每个候选标签只能进入以下四种状态之一：

| 状态 | 含义 | 进入正式标签？ |
|:--|:--|:--|
| `confirmed` | 用户直接表达或明确陈述。 | 是 |
| `inferred` | 原文未逐字出现标签名称，但存在明确、充分、方向唯一的语义证据。 | 是 |
| `review` | 存在合理可能性，但证据不足以自动进入正式标签。 | 否，进入 `review_candidates` |
| `empty` | 没有足够证据。 | 否，输出空数组 |

### 2.4 证据等级

正式标注采用四档证据等级。证据等级的核心是**从证据到标签的映射质量**：唯一性、距离、歧义程度。

| 等级 | 含义 | 判定标准 | 示例 |
|:--|:--|:--|:--|
| **E3 直接表达** | 用户直接陈述该标签对应的行为、偏好、感受或理由。 | 标签概念在原文中几乎逐字出现，或可由同义替换直接得到。 | "我就是喜欢跟朋友开黑，输赢无所谓。" → `social_belonging` |
| **E2 强推断** | 从证据到标签存在**短距离、方向唯一、低歧义**的映射。 | 只能得到一种主要解释；推断最多经过一层语义/因果跳跃。 | "我专门练枪，就是想打得更准。" → `ability_growth` |
| **E1 弱推断** | 证据存在多种合理解释，或需要多跳推断。 | 单一线索可指向多个标签；因果关系≠情绪关系；行为不能直接推出动机。 | "我每天打排位。"单独不能判断任何 M1。 |
| **E0 无证据** | 没有相关信息。 | — | 输出空标签。 |

**关键区分示例：**

| 原文 | 可支持的标签 | 不可自动支持的标签 | 原因 |
|:--|:--|:--|:--|
| "我专门练枪，就是想打得更准。" | M5=`deliberate_practice` (E3)；M1=`ability_growth` (E2) | — | 行为→明确目的→能力成长，单跳、方向唯一。 |
| "最近因为工作，没有一起开黑的朋友，所以玩得少了。" | M5=`quit_break` (E3)；M3=`group_experience_depends_on_friends` (E2) | M4=`disappointment` | 因果关系≠情绪关系；原文未表达失望。 |
| "我喜欢长一点的 TTK，因为这样操作空间更大。" | M3=`operational_space_matters` (E2/E3) | M1=`stimulation` | 需额外证据说明“为什么玩”。 |

**强制约束：**

- E1 证据不能直接成为正式标签，最多进入 `review_candidates`。
- 人口属性（城市等级、收入、能力等级）不得从语言风格、游戏偏好或语气猜测——违者视为标注错误。
- 每个标签值必须关联至少一条 evidence，包含原文引用和证据等级。
- **因果关系 ≠ 情绪关系**：行为原因可以直接支持 M3 认知，但不能自动支持 M4 情绪。

### 2.5 推断类型

正式标签除 `status` 外，还需记录推断类型。以下四个字段必须职责分离、正交使用：

| 字段 | 回答的问题 | 示例 |
|:--|:--|:--|
| `status` | 这个标签有没有进入正式标注？ | `confirmed` / `inferred` / `review` / `empty` |
| `inference_type` | 这个标签是怎么从证据得到的？ | `direct` / `semantic` / `causal` / `contextual` |
| `evidence_level` | 证据本身有多强？ | `E3` / `E2` / `E1` / `E0` |
| `confidence` | 模型认为这个标签正确的概率/分数是多少？ | 0.0–1.0 |

四个字段各司其职，禁止互相替代。例如：`evidence_level=E2` 不能靠 `confidence=0.90` 升格；`status=inferred` 也不能因 `inference_type=causal` 自动获得 E2。

#### 2.5.1 推断类型定义

| 推断类型 | 定义 | 示例 |
|:--|:--|:--|
| `direct` | 原文直接表达。 | "我玩游戏就是为了放松。" → `relaxation_escape` |
| `semantic` | 根据明确语义归纳，无因果跳跃。 | "输完以后特别窝火。" → `anger_frustration` |
| `causal` | 根据明确因果/目的关系推断，但只推进一步。 | "我练枪就是为了提高命中率。" → `ability_growth` + `deliberate_practice` |
| `contextual` | 根据当前 Segment 内明确上下文推断。 | 同一片段内行为+情绪+目的共同指向某动机。 |

> **Contextual 推断限制**
>
> 仅允许使用当前 Segment 内的信息。禁止调用常识、用户画像、其他 Segment、"这类用户通常……"、外部统计规律来补充当前 Segment 缺失的信息。

### 2.6 Confidence：从模型分数到真实概率

每个正式标签需要输出 `confidence`。confidence 应分阶段处理：

| 阶段 | 字段 | 含义 | 解释 |
|:--|:--|:--|:--|
| 未校准 | `confidence` | 模型分数 `model_score` | 模型认为证据有多明确，不等于真实正确概率。 |
| 校准后 | `calibrated_confidence` | 近似真实概率 | 经人工黄金集校准后，表示 `P(label correct \| score)`。 |

示例（未校准阶段）：

```json
{
  "label": "frustration",
  "confidence": 0.93,
  "calibrated_confidence": null,
  "calibrated": false
}
```

应解释为：模型当前认为证据非常明确，但 0.93 尚未经过人工黄金集校准，不能直接称为“真实概率 93%”。

**校准路径：**

1. **阶段一（当前）**：AI 输出模型置信度到 `confidence`，`calibrated: false`，`calibrated_confidence: null`。
2. **阶段二**：积累人工黄金集，使用 Platt Scaling、Isotonic Regression 或分桶校准方法，建立 `model_score → calibrated_confidence` 映射。
3. **阶段三**：`calibrated_confidence` 写入后，`calibrated: true`；必要时可保留原 `confidence` 作为模型分数参考。

**校准质量评测指标（必须监控）：**

| 指标 | 用途 |
|:--|:--|
| Calibration Curve | 直观检查置信度与真实准确率是否匹配。 |
| Brier Score | 综合衡量概率预测准确性与校准度。 |
| Expected Calibration Error (ECE) | 量化置信度分桶后的平均偏差。 |
| Reliability Diagram | 展示各置信度区间实际正确率。 |

未校准时，禁止将 `confidence` 直接解释为“真实概率”，也禁止用平均 confidence 替代校准指标。

### 2.7 三阶段决策流程

统一执行以下三道门禁：

```text
发现候选标签
      ↓
当前 Segment 是否有相关证据？
      ↓
     否 ─────→ EMPTY
      │
     是
      ↓
证据等级 E3 / E2 / E1 / E0？
      ↓
E1 / E0 ───→ REVIEW / EMPTY
      │
E2 / E3
      ↓
是否符合该标签允许的推断规则？
      ↓
     否 ─────→ EMPTY / REVIEW
      │
     是
      ↓
Confidence 是否达到该标签阈值？
      ↓
     否 ─────→ REVIEW / EMPTY
      │
     是
      ↓
正式标签（confirmed 或 inferred）
```

> **Confidence 不能单独决定是否标注**
>
> 错误示例：证据很弱 + 模型 confidence = 0.90 → 正式标签。**禁止。** 必须先通过证据门、推断规则门、confidence 门三道判断。

#### 2.7.1 标签特定阈值与证据上限

不同标签的误判成本不同，允许拥有不同 confidence 门槛。**evidence_level 决定 confidence ceiling，标签特定 threshold 决定是否准入。**

| 层级/标签类型 | 证据上限（E3） | 证据上限（E2） | 初始阈值参考 | 理由 |
|:--|:--|:--|:--|:--|
| M5 行为 | ≤ 1.00 | ≤ 0.90 | ≥ 0.70 | 行为通常证据直接，误判成本较低。 |
| M4 情绪 | ≤ 1.00 | ≤ 0.90 | ≥ 0.75 | 语义推断较常见，需要中等门槛。 |
| M3 认知 | ≤ 1.00 | ≤ 0.90 | ≥ 0.80 | 涉及玩家判断，需要较明确证据。 |
| M2 期待 | ≤ 1.00 | ≤ 0.90 | ≥ 0.80 | 常隐含在评价中，但规范性较强。 |
| M1 动机 | ≤ 1.00 | ≤ 0.92 | ≥ 0.85 | 深层动机错误推断风险最高，门槛最高。 |

**规则说明：**

- `confidence` 不得超过该 evidence_level 对应的 ceiling。例如 M1 的 E2 推断 confidence 最高 0.92，不能输出 0.95。
- 达到 threshold 才允许进入正式标签；达到 ceiling 但未达到 threshold 的，进入 `review_candidates` 或留空。
- 具体 ceiling 和 threshold 数值必须通过人工黄金集校准，不得以初始参考作为最终标准。

**示例：**

| 场景 | evidence_level | confidence ceiling | threshold | 结果 |
|:--|:--|:--|:--|:--|
| M1 `competitive_proof`，E3 直接表达 | E3 | 1.00 | ≥ 0.85 | confidence=0.90 → 正式标签 |
| M1 `competitive_proof`，E2 单跳因果 | E2 | 0.92 | ≥ 0.85 | confidence=0.88 → 正式标签 |
| M1 `competitive_proof`，E1 弱线索 | E1 | 0.75 | ≥ 0.85 | 禁止进入正式标签，入 review |

> 上表中的 ceiling 和 threshold 仅为结构示意，最终数字由黄金集校准确定。

### 2.8 推断限制规则

| 禁止推断 | 错误示例 | 正确做法 |
|:--|:--|:--|
| 行为不能自动推出动机 | "我每天打排位。" → M1=`competitive` | 仅标 M5=`ranked_grind`，M1 留空或 review。 |
| 行为不能自动推出情绪 | "我每天打排位。" → M4=`excitement` | M4 留空。 |
| 结果不能自动推出原因 | "我退游了。" → M1=`dissatisfaction` | 除非 Segment 说明原因，否则 M1 留空。 |
| 频率不能自动推出重要性 | "我每天都玩。" → `high_importance` | 不能推断重要性。 |
| 正面行为不能自动推出喜欢 | "我连续玩了三个月。" → `like` | 寻找明确态度证据。 |
| 负面行为不能自动推出讨厌 | "我卸载了游戏。" → `hate` | 必须寻找原因。 |

#### 2.8.1 允许合理推断，但必须有证据链

示例：

> "我专门练枪，就是想打得更准。"

证据链：练枪 → 明确目的 → 提高准确率。因此允许：

- M1 = `ability_growth`
- M5 = `deliberate_practice`

但"我每天练枪。"只有行为，只允许 M5 = `deliberate_practice`，M1 留空。

### 2.8.2 推断结果与下游使用

标签的 `status`、`inference_type` 与 `evidence_level` 共同决定其能否进入下游建模、embedding 与画像生成。统一划分为三个信任层级：

| 信任层级 | 对应字段组合 | 进入下游？ | 使用方式 |
|:--|:--|:--|:--|
| **事实层（direct）** | `status=confirmed` + `inference_type=direct` + `evidence_level=E3` | 是 | 可直接进入事实库、embedding、聚类、画像生成。 |
| **推导层（derived）** | `status=inferred` + `evidence_level=E2` + 满足该标签阈值 | 是 | 可进入 embedding、聚类、画像生成，但需按 `confidence` 加权或降级使用；M1/M2 推导需特别审慎。 |
| **推测层（speculative）** | `status=review` 或 `evidence_level=E1` | 否 | 只进入 `review_candidates`，供人工复核、规则迭代，**不得**直接进入模型训练、embedding 或聚类。 |
| **空（empty）** | 无标签或 `status=empty` | 否 | 不使用。 |

**关键规则：**

1. 下游默认只消费 **事实层** 和 **推导层** 的正式标签；`review_candidates` 对下游不可见。
2. **推导层** 的 M1 动机必须满足：
   - 同一片段内有明确的证据链（可直接来自 M5 行为 + 明确目的，也可来自 M3/M4 + 明确因果）。
   - 不允许从单一行为或结果直接跳跃到 M1。
   - 必须满足 M1 的 E2 confidence ceiling 和 threshold。
3. 同一条 Segment 允许出现 **断裂的因果链**，例如只有 M5 行为或只有 M3+M5，缺失层必须留空。
4. **Segment-level Annotation 与 Respondent-level Profile 必须分层**：
   - Segment 内证据不足 → 该 Segment 对应标签留空或 review，**禁止**为了形成完整画像而补标签。
   - Respondent Profile 通过同一用户多条 Segment 的 Evidence Pool 聚合生成；单条 Segment 的空白不否定 Respondent 层面的倾向。

### 2.9 Review Candidates

取消整段 `review_status`，统一使用 segment 级别的 `review_candidates` 字段承载不确定候选。

`review_candidates` 不是正式标签，下游 embedding、检索、画像默认只使用正式 annotations。

示例：

```json
{
  "iceberg": {
    "M1_motivation": [],
    "M2_expectation": [],
    "M3_perception": [],
    "M4_feeling": [],
    "M5_behavior": [
      { "value": "ranked_grind", "status": "confirmed", "inference_type": "direct", ... }
    ]
  },
  "review_candidates": [
    {
      "label": "competitive_proof",
      "suggested_M": "M1",
      "reason": "存在排位行为，但片段未明确表达上分/证明动机",
      "evidence_level": "E1",
      "confidence": 0.55
    }
  ]
}
```

#### 2.9.1 Review Candidates 的作用

1. **人工复核**：发现模型经常在某种语境下产生某标签，但现有规则不够明确。
2. **规则优化**：统计 `review_candidates` 高频标签，判断某些标签是否应放宽准入条件。
3. **标签体系优化**：发现大量候选集中在新语义区域，说明可能缺少一个标签。

### 2.10 标签互斥与共存

每个标签在标签字典中必须声明：

- `mutually_exclusive`：与该标签互斥的标签列表。
- `co_occurrence_allowed`：允许与该标签共存的标签列表。
- `attribute_axis`：该标签所属的属性轴（如 M1 动机轴、mode 结构轴、情绪效价轴等）。

AI 不允许自行决定标签之间的逻辑关系。

**默认规则（修改后）：**

- **同一 `attribute_axis` 内**：若两个标签的关系未在字典中声明，默认视为 **互斥**，需要人工 review 后才能在同一 Segment 中共存。
- **跨 `attribute_axis`**：若关系未声明，默认视为 **允许共存**，但每个标签仍需独立证据。

**禁止规则：**

- 不允许使用"关系未声明 = 自动允许共存"作为同一属性轴内的默认假设。
- 同一 Segment 内、同一触发事件中，互斥标签不能同时成立。

#### 2.10.1 互斥示例

- `pure_pve` 与 `pure_pvp` 在 mode 结构中互斥。
- 风格轴两端（如 `aggressive` 与 `passive`）互斥。
- 同一情绪标签的相反效价（如 `joy` 与 `anger_frustration`）在单一触发事件中通常互斥，但同一长片段中不同事件可共存。

#### 2.10.2 共存示例

- `achievement` + `excitement` + `competition` 在"翻盘五杀"类片段中允许共存。
- `ability_growth` + `competitive_proof` 可同时作为 M1，但需分别独立证据。

### 2.11 外部知识与 Profile 限制

> **禁止将外部知识作为当前用户证据**
>
> 基础 Segment Annotation 默认只允许使用：
> - 当前 Segment
> - 标注规范
> - 标签字典
>
> 禁止将以下信息作为当前 Segment 的证据：其他用户、其他 Segment、用户 Profile、互联网常识、统计规律、模型自身经验。

**允许使用的外部知识：**

- 标签定义、标签字典、标注规范中可以包含研究者总结的领域知识。例如：`ranked_grind` 的定义可以说明“排位赛是一种竞技模式”。
- 但禁止把领域知识当作当前用户的证据。例如：不能因为“排位赛是竞技模式”而给只说“我打排位”的用户自动标注 M1 = `competitive_proof`。

Profile 信息与 Segment Annotation 分开。即使 Respondent-level Profile 已知用户喜欢竞技游戏，也不能给当前 Segment 自动增加 M1 = `competition`。**Profile 不得反向污染 Segment Annotation。**

**整体数据流：**

```text
Raw Transcript
      ↓
Cleaning
      ↓
Segment
      ↓
Segment Annotation（仅当前 Segment 证据）
      ↓
Evidence Pool
      ↓
Respondent-level Aggregation
      ↓
Respondent Profile
      ↓
Embedding / Retrieval / Simulation
```

Segment Annotation 负责忠实记录单片段证据；Respondent Profile 负责跨片段聚合。

### 2.12 与 Embedding 的关系

基础 Embedding 输入为 `cleaned_text`；Annotation 作为结构化语义 metadata。

不要把大量标签直接拼接到原文中作为默认 Embedding 输入。后续可通过实验比较：

- A: `cleaned_text`
- B: `cleaned_text + selected annotations`
- C: `cleaned_text + semantic representation`

最终用真实检索任务评价哪种效果最好。

## 3 冰山五层标签字典

### 3.1 M1 动机/诉求

标注时机：片段表达了"为什么玩这个游戏/这个模式"的根本原因。

每条片段最多标注 3 个动机。首个标注的动机自动标记为 `primary: true`。

#### 3.1.1 竞技证明 `competitive_proof`

- **定义**：通过排名、段位、胜负来证明自身能力，获得社会认可。
- **正例**："我打排位就是为了上分，看到段位涨了特别有成就感。"
- **反例/禁止推断**：不能仅因"打排位"推断；不能因"赢了"推断。
- **Evidence**：E3 直接表达上分/段位/排名/证明；E2 行为+情绪明确指向证明。
- **Confidence 阈值**：≥ 0.85
- **互斥**：`relaxation_escape`（同一模式/场景下）
- **共存**：`stimulation`, `social_belonging`, `team_cooperation`, `ability_growth`

#### 3.1.2 能力成长 `ability_growth`

- **定义**：追求技术、意识、操作的持续进步。
- **正例**："我专门练枪，就是想打得更准。"
- **反例/禁止推断**："我每天练枪"单独不能推断；必须有明确成长目的。
- **Evidence**：E3 明确表达"变强/进步/学习"；E2 练习行为+明确成长目的。
- **Confidence 阈值**：≥ 0.85
- **互斥**：无
- **共存**：`competitive_proof`, `stimulation`, `strategy_mastery`

#### 3.1.3 支配优越 `dominance`

- **定义**：追求碾压、统治、让对手服气的优越感。
- **正例**："我就喜欢虐菜，那种掌控全局的感觉很爽。"
- **反例/禁止推断**："我打得很好"不能推断为支配优越。
- **Evidence**：E3 明确表达"碾压/虐菜/统治/让别人服"。
- **Confidence 阈值**：≥ 0.85
- **互斥**：`relaxation_escape`
- **共存**：`competitive_proof`, `stimulation`

#### 3.1.4 团队协作 `team_cooperation`

- **定义**：享受与队友配合、共同完成目标的过程。
- **正例**："我们五个人配合好了，那种默契特别舒服。"
- **反例/禁止推断**："和朋友玩"不能自动推断为团队协作；可能只是社交归属。
- **Evidence**：E3 明确表达"配合/默契/团队目标"；E2 具体配合行为+正面反馈。
- **Confidence 阈值**：≥ 0.85
- **互斥**：无
- **共存**：`social_belonging`, `competitive_proof`

#### 3.1.5 社交归属 `social_belonging`

- **定义**：通过游戏维系朋友关系、获得归属感。
- **正例**："朋友不玩了我也不想上了。"
- **反例/禁止推断**："和朋友开黑"不能单独推断；可能是减压或习惯。
- **Evidence**：E3 明确表达"朋友/社交/圈子/归属感"；E2 社交依赖行为+情绪。
- **Confidence 阈值**：≥ 0.85
- **互斥**：无
- **共存**：`team_cooperation`, `relaxation_escape`

#### 3.1.6 射击爽感 `stimulation`

- **定义**：追求射击反馈、打击感、枪感带来的即时快感。
- **正例**："这游戏枪感太爽了，爆头那一下特别解压。"
- **反例/禁止推断**："游戏好玩"不能自动推断为射击爽感。
- **Evidence**：E3 明确表达"枪感/打击感/爆头快感/手感"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`competitive_proof`, `ability_growth`, `dominance`

#### 3.1.7 放松逃避 `relaxation_escape`

- **定义**：把游戏作为放松、解压、逃避现实压力的方式。
- **正例**："每天下班回家打两把，什么也不想，就放松一下。"
- **反例/禁止推断**："我玩得很开心"不能推断为放松逃避。
- **Evidence**：E3 明确表达"放松/解压/逃避/不费脑/休闲"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：`competitive_proof`, `dominance`（同一模式/场景下）
- **共存**：`social_belonging`, `sensory_aesthetics`, `narrative_immersion`

#### 3.1.8 策略掌控 `strategy_mastery`

- **定义**：享受战术博弈、算计、智商压制的乐趣。
- **正例**："我最喜欢研究对面走位，提前预判他们的动作。"
- **反例/禁止推断**："我会绕后"不能推断为策略掌控。
- **Evidence**：E3 明确表达"策略/战术/博弈/算计/智商压制"。
- **Confidence 阈值**：≥ 0.85
- **互斥**：无
- **共存**：`ability_growth`, `competitive_proof`

#### 3.1.9 探索收集 `exploration_collection`

- **定义**：追求探索地图、收集皮肤/成就/全图鉴。
- **正例**："我喜欢把每个地图的角落都跑一遍，收集全皮肤。"
- **反例/禁止推断**："我买皮肤"不能自动推断为收集动机；可能是社交展示。
- **Evidence**：E3 明确表达"探索/收集/成就/全图鉴"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`sensory_aesthetics`, `expression_creation`

#### 3.1.10 叙事沉浸 `narrative_immersion`

- **定义**：被剧情、世界观、角色故事吸引。
- **正例**："我就是冲着剧情来的，想知道后面发生了什么。"
- **反例/禁止推断**："画面好"不能推断为叙事沉浸。
- **Evidence**：E3 明确表达"剧情/世界观/代入感/角色/故事"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`sensory_aesthetics`, `relaxation_escape`

#### 3.1.11 视听审美 `sensory_aesthetics`

- **定义**：被画面、美术、音乐、特效吸引。
- **正例**："这个游戏的画面和音乐太棒了，光看着就舒服。"
- **反例/禁止推断**："皮肤好看"单独不能推断；需明确指向视听审美体验。
- **Evidence**：E3 明确表达"画面/美术/音乐/皮肤好看/特效"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`narrative_immersion`, `exploration_collection`

#### 3.1.12 表达创造 `expression_creation`

- **定义**：通过自定义、DIY、创作表达自我。
- **正例**："我喜欢自己配枪，打造一套独特的装备外观。"
- **反例/禁止推断**："我买了皮肤"不能推断为表达创造。
- **Evidence**：E3 明确表达"创造/自定义/DIY/表达自己/独特"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`exploration_collection`, `sensory_aesthetics`

### 3.2 M2 期待/标准

标注时机：片段表达了"游戏应该怎样"或"好游戏的标准是什么"。

每条片段最多标注 2 个 M2 标签。期待往往隐含评价（"XX 不好" → 期待的是 XX 的反面）。

#### 3.2.1 公平竞技 `fair_competition`

- **定义**：游戏应保证竞技公平，包括匹配、反外挂、平衡性。
- **正例**："匹配机制太垃圾了，总是排到段位高很多的。"
- **反例/禁止推断**："对面太强"是 M3 认知，不是 M2 期待。
- **Evidence**：E3 明确表达"公平/平衡/匹配机制/同水平"；E2 抱怨现状隐含公平期待。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`skill_determines`, `monetization_fair`

#### 3.2.2 技术决定 `skill_determines`

- **定义**：胜负应由技术决定，不应靠运气或付费。
- **正例**："竞技游戏就该看技术。"
- **反例/禁止推断**："我枪法好"不能推断为技术决定期待。
- **Evidence**：E3 明确表达"技术决定胜负/实力说话"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`fair_competition`, `monetization_fair`

#### 3.2.3 丰富内容 `rich_content`

- **定义**：希望游戏内容多、更新快、玩法多样。
- **正例**："内容太少了，玩两个月就腻了。"
- **反例/禁止推断**："我玩了两个月"不能推断为内容少。
- **Evidence**：E3 明确表达"内容多/更新快/新地图/新武器"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`continuous_challenge`

#### 3.2.4 社交便利 `social_convenience`

- **定义**：希望组队、语音、社交系统方便。
- **正例**："组队太麻烦了，要是有更好的组队系统就好了。"
- **反例/禁止推断**："我和朋友玩"不能推断为社交便利期待。
- **Evidence**：E3 明确表达"组队方便/语音/社交系统"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`positive_community`

#### 3.2.5 低门槛 `low_barrier`

- **定义**：希望上手简单、新手友好、不肝不氪。
- **正例**："这游戏对新手不太友好，我朋友进来玩了两把就跑了。"
- **反例/禁止推断**："我新手"不能推断为低门槛期待。
- **Evidence**：E3 明确表达"上手简单/新手指引/不肝/不氪"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`respect_time`

#### 3.2.6 沉浸体验 `immersive_experience`

- **定义**：希望画面、音效、氛围、代入感好。
- **正例**："画面和音效太棒了，很有代入感。"
- **反例/禁止推断**："画面好"单独是 M3 认知，除非表达"应该这么好"。
- **Evidence**：E3 明确表达"画面好/音效/氛围/代入感/真实感"并带规范意味。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：无

#### 3.2.7 正向社区 `positive_community`

- **定义**：希望社区环境好、玩家素质高。
- **正例**："社区环境好差，到处都是喷子。"
- **反例/禁止推断**："队友骂我"是单次体验，不一定是对社区的规范性期待。
- **Evidence**：E3 明确表达"社区好/玩家素质/不骂人/友善"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`social_convenience`

#### 3.2.8 持续挑战 `continuous_challenge`

- **定义**：希望游戏有持续挑战、不会腻、有终局内容。
- **正例**："后期没什么挑战了，很快就腻了。"
- **反例/禁止推断**："我玩了很久"不能推断为持续挑战期待。
- **Evidence**：E3 明确表达"有挑战/不会腻/难度曲线/终局内容"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`rich_content`

#### 3.2.9 尊重时间 `respect_time`

- **定义**：不希望被强制在线时长、日常任务绑架。
- **正例**："日常任务太肝了，不肝又跟不上。"
- **反例/禁止推断**："我玩得少"不能推断为尊重时间期待。
- **Evidence**：E3 明确表达"不应强制在线/日常任务不要太肝"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`low_barrier`

#### 3.2.10 付费公平 `monetization_fair`

- **定义**：付费不应影响竞技公平，皮肤可以贵但不能加属性。
- **正例**："皮肤贵一点没关系，但不能加属性。"
- **反例/禁止推断**："我不充钱"不能推断为付费公平期待。
- **Evidence**：E3 明确表达"付费不应影响竞技公平/皮肤可以贵不能加属性"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`fair_competition`, `skill_determines`

#### 3.2.11 队友沟通 `teammate_communication`

- **定义**：期待队友愿意沟通、报点、听指挥。
- **正例**："队友要沟通，不报点根本没法打。"
- **反例/禁止推断**："队友不说话"是描述现状，不一定构成期待。
- **Evidence**：E3 明确表达"队友要沟通/报点/听指挥"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`teammate_competence`, `teammate_stability`

#### 3.2.12 队友能力 `teammate_competence`

- **定义**：期待队友水平与自身匹配。
- **正例**："队友不能太菜，水平要差不多。"
- **反例/禁止推断**："队友坑"可能是情绪发泄，不一定构成规范性期待。
- **Evidence**：E3 明确表达"队友水平要差不多/不能太菜"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`teammate_communication`, `teammate_stability`

#### 3.2.13 队友情绪稳定 `teammate_stability`

- **定义**：期待队友心态好、不随便喷人。
- **正例**："不要动不动就喷人，心态好一点。"
- **反例/禁止推断**："队友喷我"是单次事件描述。
- **Evidence**：E3 明确表达"心态好/不要喷人/情绪稳定"。
- **Confidence 阈值**：≥ 0.80
- **互斥**：无
- **共存**：`teammate_communication`, `teammate_competence`

### 3.3 M3 认知/观点

标注时机：片段中表达了"XX 是什么/怎么样"的判断、评价、归因。

每条片段最多标注 2 个 M3 标签。M3 是五个层次中最多样化的，优先从已有分类匹配，无法匹配时用 `category: "other"` 并写明具体内容。

| 分类 | 英文 key | 常见标签示例 | 阈值 |
|:--|:--|:--|:--|
| 公平性感知 | `fairness_perception` | `matchmaking_unfair`, `cheater_problem`, `aim_assist_harms_fairness` | ≥ 0.80 |
| 难度感知 | `difficulty_perception` | `too_steep`, `ceiling_too_high`, `unfriendly_to_newbies` | ≥ 0.80 |
| 深度感知 | `depth_perception` | `content_too_little`, `gets_boring_fast`, `lacks_strategy_depth` | ≥ 0.80 |
| 品质感知 | `quality_perception` | `good_graphics`, `poor_optimization`, `good_gunfeel` | ≥ 0.80 |
| 商业化感知 | `monetization_perception` | `too_expensive`, `gacha_is_bad`, `f2p_unfriendly` | ≥ 0.80 |
| 版本环境感知 | `meta_perception` | `meta_dominated`, `certain_weapon_op` | ≥ 0.80 |
| 自我能力定位 | `self_ability` | `i_am_novice`, `i_am_advanced`, `reaction_slowed` | ≥ 0.80 |
| 自我身份认同 | `self_identity` | `competitive_player`, `casual_player` | ≥ 0.80 |
| 自我限制认知 | `self_limitation` | `hand_speed_limit`, `cannot_improve` | ≥ 0.80 |
| 对队友 | `teammate_perception` | `teammates_are_bad`, `randoms_uncooperative` | ≥ 0.80 |
| 对对手 | `opponent_perception` | `opponents_too_strong`, `smurf_problem` | ≥ 0.80 |
| 对厂商 | `developer_perception` | `dev_only_wants_money`, `poor_operation` | ≥ 0.80 |
| 对社区 | `community_perception` | `community_toxic`, `community_friendly` | ≥ 0.80 |
| 因果归因 | `causal_attribution` | `quit_because_cheaters`, `joined_because_friends` | ≥ 0.80 |

#### 3.3.1 M3 标注规则

- 区分 M3 认知和 M2 期待：M3 是"实际是怎样"，M2 是"应该怎样"。
- 区分 M3 认知和 M5 行为：M3 是"怎么看"，M5 是"怎么做"。
- 玩家引用别人观点但明确不认同，只记录玩家自己的立场。
- 反问和讽刺要结合上下文，不能按字面标注。
- 品牌刻板印象可以标注，但必须保留为"玩家观点"，不能写成事实。

### 3.4 M4 感受/情绪

标注时机：片段中明确表达了情绪状态或情感反应。

每条片段最多标注 2 个情绪。情绪标注必须原文有明确的情感词或强烈的情绪语境。

| 标签 | 英文 key | 识别信号 | 效价 | 阈值 |
|:--|:--|:--|:--:|:--|
| 兴奋/激动 | `excitement` | "爽""刺激""激动""肾上腺素" | + | ≥ 0.75 |
| 成就感 | `achievement` | "成就感""满足""骄傲""自豪" | + | ≥ 0.75 |
| 沉浸/心流 | `flow` | "沉浸""忘记时间""心流""投入" | + | ≥ 0.75 |
| 快乐/愉悦 | `joy` | "开心""好玩""快乐""有意思" | + | ≥ 0.75 |
| 社交温暖 | `social_warmth` | "感动""温暖""归属感""被认可" | + | ≥ 0.75 |
| 愤怒/挫败 | `anger_frustration` | "气死""烦""砸键盘""想删游戏""挫败" | − | ≥ 0.75 |
| 焦虑/紧张 | `anxiety_tension` | "紧张""手心出汗""不敢打""压力" | − | ≥ 0.75 |
| 无聊/倦怠 | `boredom_burnout` | "无聊""腻了""没意思""倦怠" | − | ≥ 0.75 |
| 失望/失落 | `disappointment` | "失望""没意思了""凉了""退坑""被背叛" | − | ≥ 0.75 |
| 麻木/无所谓 | `numbness` | "无所谓""习惯了""麻木" | 0 | ≥ 0.75 |

#### 3.4.1 情绪维度

每个 M4 标注必须包含：

- **强度 `intensity`**：`low` | `medium` | `high`
- **触发 `trigger`**：`win_loss` | `growth` | `team` | `matchmaking` | `monetization` | `cheat` | `performance` | `content` | `social`
- **效价 `valence`**：`positive` | `negative` | `neutral`

#### 3.4.2 M4 边界

- "累"需要区分身体/注意力疲劳（精力资产）和情绪厌倦（M4）。
- "我觉得不公平"通常是 M3 评价；若同时有"很生气"，再标 M4。
- "还行吧""一般"是中性评价，不标为兴奋或快乐。

#### 3.4.3 M4 互斥与共存

- 同一触发事件内，`joy` 与 `anger_frustration` 通常互斥。
- `excitement` 与 `achievement` 在胜利/成长类事件中允许共存。
- `boredom_burnout` 与 `flow` 互斥。

### 3.5 M5 行为/应对

标注时机：片段中描述了具体的游戏行为、习惯、应对方式。

每条片段最多标注 3 个行为。必须是具体可观察的行为，不是态度或倾向。

| 标签 | 英文 key | 定义 | 正例 | 反例/禁止推断 | 阈值 |
|:--|:--|:--|:--|:--|:--|
| 排位/上分 | `ranked_grind` | 主动参与排位、冲分、爬段位。 | "我每天下班打排位上分。" | "我玩过排位"不一定当前仍在打。 | ≥ 0.70 |
| 刻意练习 | `deliberate_practice` | 去训练场、练枪房等针对性练习。 | "我每天去训练场练十分钟枪。" | "我想练枪"是计划，标 `planned`。 | ≥ 0.70 |
| 看攻略/学习 | `watch_guides` | 主动看攻略、视频、直播学习。 | "我没事就看职业选手直播学技术。" | "我看过一次攻略"只能标 `occasional`。 | ≥ 0.70 |
| 社交开黑 | `social_play` | 主动和朋友/熟人组队游玩。 | "我周末都和朋友五排。" | "打过一把双排"不一定是社交开黑习惯。 | ≥ 0.70 |
| 休闲匹配 | `casual_play` | 玩非排位匹配、娱乐模式。 | "排位输了我就去打匹配放松一下。" | 不能因"不打排位"推断为休闲匹配。 | ≥ 0.70 |
| 切换模式/产品 | `switch_mode` | 在不同模式或游戏间切换以调节体验。 | "连输两把就去打娱乐模式。" | "我玩很多游戏"不能推断为切换行为。 | ≥ 0.70 |
| 回流 | `return` | 离开一段时间后重新回来玩。 | "好久没玩了又回来，发现变化很大。" | "我以前玩过"不能推断为回流。 | ≥ 0.70 |
| 回避陌生人 | `avoid_strangers` | 避免与随机路人组队或交流。 | "我只跟熟人玩，不打路人局。" | "路人局体验差"是 M3，不一定是行为。 | ≥ 0.70 |
| 内容分享 | `content_share` | 主动分享战绩、视频、内容到社交平台。 | "我经常会剪辑精彩操作发到 B 站。" | "我看过别人发的视频"不能推断。 | ≥ 0.70 |
| 消费/氪金 | `spending` | 在游戏内进行付费消费。 | "我买皮肤/氪金/充钱/抽奖。" | "皮肤好看"是态度，不是消费行为。 | ≥ 0.70 |
| 退坑/休息 | `quit_break` | 明确退游、删游戏、休息一段时间。 | "我退坑了/删游戏了/不玩了。" | "最近玩得少"不能推断为退坑。 | ≥ 0.70 |
| 换号/炸鱼 | `smurf` | 使用小号、炸鱼行为。 | "我开了个小号去低段位玩。" | "我用过几个号"不能推断为炸鱼。 | ≥ 0.70 |
| 追比赛/电竞 | `watch_esports` | 观看比赛、追战队、看职业。 | "我每天晚上都看比赛。" | "看过一次比赛"只能标 `occasional`。 | ≥ 0.70 |
| 社区参与 | `community_engage` | 发帖、贴吧、加群、讨论。 | "我经常在贴吧看攻略帖。" | "我加了群"不一定参与讨论。 | ≥ 0.70 |

#### 3.5.1 行为频率标注

行为标签需要标注 `frequency`（如原文有提及）：

- `daily`：每天
- `regular`：经常/规律性
- `occasional`：偶尔
- `past`：过去做过但现在不做了
- `planned`：明确计划但尚未执行

除非原文提到频率，否则不标注 `frequency`。

### 3.6 跨层关系矩阵

以下矩阵汇总 M1-M5 之间的常见推断关系。

| 源层 | 目标层 | 关系 | 说明 |
|:--|:--|:--|:--|
| M5 行为 | M1 动机 | **禁止自动推断** | 行为不能直接推出动机。 |
| M5 行为 | M4 情绪 | **禁止自动推断** | 行为不能直接推出情绪。 |
| M4 情绪 | M1 动机 | **需要额外证据** | 情绪可能指向多种动机，需明确原因。 |
| M4 情绪 | M5 行为 | **需要额外证据** | 情绪不一定导致特定行为。 |
| M3 认知 | M2 期待 | **需要额外证据** | 认知是"实际怎样"，期待是"应该怎样"。 |
| M2 期待 | M1 动机 | **需要额外证据** | 期待反映价值观，不直接等于动机。 |
| M5 + M4 + 明确目的 | M1 | **允许推断** | 行为+情绪+明确目的共同指向动机。 |
| M5 + 明确因果 | M3 | **允许推断** | 行为+因果陈述可支持认知标签。 |

## 4 框架七维标注规范

框架维度包括七个子维度：诉求、能力、风格、平台、模式、资产、甜区。前五个为一级展示维度，资产和甜区为扩展研究维度。

### 4.1 诉求（Needs）

与冰山 M1 高度重合。值域与 M1 一致。当 M1 标注了某动机时，框架 `needs.primary` 或 `needs.secondary` 应保持一致。

规则：

- 片段表达明确诉求 → `primary` + 可选 `secondary`。
- 诉求隐含 → 可标 `primary`，但 confidence 降低。
- 无法判断 → `needs` 为空。

### 4.2 能力（Ability）

#### 4.2.1 综合等级

| 标签 | 英文 key | 识别信号 |
|:--|:--|:--|
| 新手 | `novice` | "刚玩""不太会""菜鸟""新手""接触不久" |
| 入门 | `beginner` | "会一点""基本操作""刚上手" |
| 进阶 | `intermediate` | "差不多""平均水平""还行" |
| 高手 | `advanced` | "厉害""高手""能打""段位高" |
| 专家/竞技级 | `expert` | "职业""比赛""顶级""天花板" |
| 未知 | `unknown` | 片段中无法判断能力水平 |

判定证据优先级：

1. 可核验成绩：段位、赛事、命中率、稳定表现。
2. 具体技巧叙述及自我诊断。
3. 行为证据：训练、复盘、战术沟通。
4. 自我评价。
5. 语气或游戏时长——只能作弱证据。

> **禁止推断**
>
> - 玩得久 = 高手
> - PC 玩家 = 能力高
> - 男性 = 枪法强
> - 高付费 = 能力强
> - 喜欢 PVE = 能力弱

#### 4.2.2 技巧强项与短板

值域：枪法、身法、信息获取、战场策略、品类知识五大类。强项和短板各最多 3 个。同一子项不能同时出现在强项和短板。

### 4.3 风格（Style）

3 组双极轴 + 2 组扩展轴：

| 轴 | 左端 | 中间 | 右端 |
|:--|:--|:--|:--|
| 战斗倾向 | 苟活避战 | 灵活平衡 | 主动求战/刚枪 |
| 决策方式 | 仔细思考/策略 | 情境切换 | 本能快速反应 |
| 取胜方式 | 团队协作取胜 | 团队个人平衡 | 个人能力取胜 |
| 成长方式 | 数值养成 | 混合 | 操作技巧对抗 |
| 社交方式 | 熟人开黑 | 均可 | 陌生人/单人 |

每组轴单选。如果原文明确两端行为按场景变化，标为中间态并记录条件。

### 4.4 平台（Platform）

| 标签 | 英文 key |
|:--|:--|
| PC | `pc` |
| 主机 | `console` |
| 手机 | `mobile` |
| 多平台均衡 | `multi_platform` |
| 云游戏/其他 | `cloud_other` |
| 未知 | `unknown` |

主选平台单选，次选平台可选。必须区分"当前使用平台"和"真实偏好平台"。

### 4.5 模式（Mode）

#### 4.5.1 主结构

| 标签 | 英文 key |
|:--|:--|
| 纯 PVE | `pure_pve` |
| PVE 为主 | `pve_main` |
| PVP/PVE 均衡 | `balanced` |
| PVP 为主 | `pvp_main` |
| 纯 PVP | `pure_pvp` |
| 随场景变化 | `contextual` |

五档主结构单选。"纯 PVE"与任何 PVP 主结构互斥；"纯 PVP"与任何 PVE 主结构互斥。

#### 4.5.2 二级模式

每个二级模式标注三态：`liked` / `avoided` / `not_experienced`。

### 4.6 游戏资产（Assets）

五类资产，每类四档：充足 / 有约束 / 严重稀缺 / 未知。

- `time`：时间
- `ability_asset`：能力
- `energy`：精力
- `emotion`：情绪
- `money`：金钱

注意："不愿付费"不等于金钱稀缺；"只玩短局"不一定时间稀缺；"觉得累"需明确是注意力负荷还是内容厌倦。

### 4.7 甜区体验（Sweet Spot）

| 字段 | 英文 key | 值域 |
|:--|:--|:--|
| 阶段 | `stage` | 新手理解 / 快速提升 / 稳定精通 / 平台期 / 流失期 / 未知 |
| 甜区技巧数 | `skill_count` | 整数 |
| 甜区长度 | `duration` | 短 / 中 / 长 / 未知 |
| 甜区质量 | `quality` | 低 / 中 / 高 / 未知 |
| 心流因子 | `flow_factors` | 多选：目标清晰、反馈即时、技巧挑战平衡、控制感、专注、行动意识融合、忘我、时间感变化、自目的体验 |
| 峰值体验 | `peak_moment` | 玩家描述的峰值事件原文 |
| 平台/流失触发 | `plateau_trigger` | 平台期或流失触发原因原文 |

## 5 产品评测扩展标签

产品评测扩展标签覆盖客观与场景、题材与美术、玩法偏好、社交结构、商业化、内容与营销、生命周期、容忍阈值等维度。它们是偏好或决策条件，不直接等同于 M1 动机。

### 5.1 态度等级通用规则

标注偏好必须区分态度等级：

- `liked`：明确喜欢。
- `accepted`：不特别喜欢，但可以接受。
- `neutral`：无明显态度。
- `disliked`：明确不喜欢。
- `rejected`：会因此拒绝下载/退游。
- `not_experienced`：未体验。
- `unknown`：没说。

### 5.2 主要扩展维度

| 维度 | 英文 key | 说明 |
|:--|:--|:--|
| 客观与场景 | `demographics` | 城市等级、生活阶段、设备环境、游玩时段。 |
| 题材与美术 | `style_preference` | 题材、美术风格。 |
| 玩法偏好 | `gameplay_preference` | 视角、TTK、对局时长、复活机制、地图、系统。 |
| 社交结构 | `social_structure` | 固定队、熟人偶尔开黑、路人组队、单人/孤狼、公会。 |
| 商业化 | `monetization` | 付费水平、付费方式、付费动机、公平边界。 |
| 内容与营销 | `content_marketing` | 信息渠道、内容偏好、信任来源。 |
| 生命周期 | `lifecycle` | 迁移触发、流失原因、召回条件、版本期待。 |
| 容忍阈值 | `tolerance` | 匹配等待、外挂容忍、卡顿容忍、强制组队、学习成本。 |

## 6 因果链标注

当一条片段中同时出现了多个层次，且明确表达了因果关系时，标注证据与标签结论之间的因果链。因果链的基本单元是 **evidence → claim → claim**，而不是 M5 → M4 → M3 → M2 → M1 的标签链。

### 6.1 单片段因果链结构

```json
{
  "causal_chain": [
    {
      "from": "evidence_01",
      "from_value": "为了上分",
      "to": "M1:competitive_proof",
      "relation": "supports"
    },
    {
      "from": "evidence_02",
      "from_value": "打排位",
      "to": "M5:ranked_grind",
      "relation": "supports"
    },
    {
      "from": "M1:competitive_proof",
      "from_value": "competitive_proof",
      "to": "M5:ranked_grind",
      "relation": "causes"
    }
  ]
}
```

**字段说明：**

| 字段 | 说明 |
|:--|:--|
| `from` | 起点类型：`evidence_XX` 或 `MX:label_key`。 |
| `from_value` | 起点的具体内容或标签值。 |
| `to` | 终点类型：`MX:label_key`。 |
| `relation` | 关系类型：`supports`（证据支持标签）、`causes`（一个标签导致另一个标签）、`correlates`（相关但非因果）。 |

### 6.2 规则

- 因果链只在**同一片段中明确表达了因果关系**时标注。
- 不跨片段推断因果链。
- **优先建立 evidence → claim 的 support 关系**，再建立 claim → claim 的 cause/correlate 关系。
- M5 → M4、M4 → M1 等跨层因果关系不是天然成立的；必须有片段内的明确语义支持。
- 反向推断必须标注置信度，不得把行为唯一归因于某动机。
- 不要求每个片段都有五层——单片段通常只覆盖 1–3 层。

### 6.3 跨片段聚合

同一用户的所有因果链片段汇总后：

- 高频因果路径 → 该画像的"典型动机链"。
- 矛盾路径保留，标记为 `context_dependent`。
- 完整心智链应在同一用户的多条证据上聚合，而非单条片段强行拼凑。

## 8 质量管控标准

### 8.1 核心质量指标

| 指标 | 目标值 | 计算方式 |
|:--|:--:|:--|
| 标注覆盖率 | ≥ 80% | 有至少一个标签的片段数 / 总片段数 |
| 平均 Confidence | 监控 | 所有标注 `confidence` 的均值；**未校准时不得作为质量目标**。 |
| 待复核率 | ≤ 15% | 有 review_candidates 的片段占比 |
| 空标率 | ≤ 20% | 无任何标注的片段占比（含填充词片段） |
| **Unsupported Label Rate** | ≤ 3% | 没有足够证据支持的正式标签比例 |
| **Valid Miss Rate** | ≤ 10% | 有充分证据但 AI 未标出的比例 |
| 推断率 | 监控 | inferred 标签占比 |
| 错误推断率 | 监控 | 被人工判定为错误的 inferred 标签占比 |
| 一致性 | ≥ 85% | 同类语句是否稳定输出相同标签 |
| Inter-annotator Agreement | ≥ 0.75 | Cohen's Kappa |
| **Calibration Curve** | 监控 | 按 confidence 分桶，绘制预测置信度 vs 真实正确率。 |
| **Brier Score** | 监控 | 概率预测准确性与校准度的综合指标。 |
| **Expected Calibration Error (ECE)** | 监控 | 置信度分桶后的平均偏差。 |
| **Reliability Diagram** | 监控 | 可视化校准质量。 |

> **关于 Unsupported Label Rate**
>
> 这是核心质量门禁。少标一个标签通常只是 Recall 损失；错误制造一个深层用户特征，则可能污染用户画像、Embedding 检索和后续分析。我们宁愿牺牲一部分 Recall，也不能让 Unsupported Label Rate 失控。

> **关于 Valid Miss Rate**
>
> 如果 Unsupported Label Rate 很低但 Valid Miss Rate 很高，说明模型太保守。此时不能简单降低所有 confidence threshold，而应该找到具体标签和具体语境，修改该标签的判定规则。

### 8.2 质量闭环

```text
标签体系
    ↓
标注
    ↓
Evidence + Inference + Confidence
    ↓
自动门禁
    ↓
Confirmed / Inferred / Review / Empty
    ↓
人工黄金集
    ↓
Precision / Recall / Unsupported Label Rate / Valid Miss Rate
    ↓
发现问题标签
    ↓
修改该标签规则
    ↓
重新测试
    ↓
冻结版本
```

### 8.3 黄金案例标准

黄金案例是用研专家人工标注的高质量样本，作为 Few-shot Prompt 的示例。

| 标准 | 要求 |
|:--|:--|
| 覆盖度 | 12 种动机各至少 2 条，5 个维度各至少 3 条 |
| 清晰度 | 原文表达明确，不存在歧义 |
| 复杂度 | 至少 5 条包含多动机、混合情绪、因果链 |
| 长度 | 原文 30-300 字，信息密度适中 |
| 来源 | 来自至少 5 个不同研究项目 |
| 数量 | 30 条（当前）→ 目标 50-100 条 |

### 8.4 常见标注错误

| 错误类型 | 错误示例 | 正确做法 |
|:--|:--|:--|
| 层次混淆 | 把"我觉得排位机制很公平"标为 M2 | 这表达的是认知 M3，不是期待 M2 |
| 过度推断 | 原文只说"玩得挺开心"，标注 M1=["竞技证明"] | 没有证据表明开心来自竞技证明 |
| 标签越界 | 用不在值域内的自定义标签 | 优先从已有标签库匹配 |
| 忽略语境 | 不看 preceding_question 就标注 | 语境可能完全改变片段含义 |
| 情绪过标 | 原文"还行吧"，标注 M4=["兴奋/激动"] | "还行"是中性评价 |
| 频率误标 | 原文只说"我练枪"，标注 frequency="daily" | 除非原文提到频率，否则不标 |
| confidence 替代证据 | E1 证据 + confidence=0.90 → 正式标签 | 必须通过证据门和推断规则门 |
