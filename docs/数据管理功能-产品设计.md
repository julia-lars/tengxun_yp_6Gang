# 数据管理功能 — 产品设计方案

> 2026-08-24 · 6Gang 射击品类 AI 模拟用户系统

---

## 一、设计目标

当前系统有 13,297 条用户原声片段、307 位受访者、5 个画像、2 个 KOL 分身，数据量已不小，但管理手段只有命令行和 pgweb。本次设计的目标是：

1. **看得见** — 数据库核心表的数据可视化浏览，支持搜索、筛选、排序
2. **改得了** — 单条编辑、批量操作，关键字段有校验
3. **进得来** — `data/` 目录下 30+ 个 JSON 文件能一键导入数据库
4. **可追溯** — 所有修改操作记录审计日志，删除有引用保护

---

## 二、信息架构

```
/admin                       数据管理首页（仪表盘）
  ├── /source-segments        用户原声片段（13,297 条）
  │   ├── /:id                 片段详情 + 编辑
  │   └── /new                 新增片段
  ├── /personas               用户画像（5 条）
  │   ├── /:id                 画像详情 + 编辑
  │   └── /new                 新增画像
  ├── /respondents            受访者（307 条）
  │   ├── /:id                 受访者详情 + 编辑
  │   └── /new                 新增受访者
  ├── /kol-profiles           KOL 画像（2 条）
  ├── /kol-segments           KOL 语料（6 条）
  ├── /import                 数据导入向导
  └── /audit-log              操作审计日志
```

### 导航设计

侧边栏「研究工具」分组下新增「数据管理」入口，点击进入 `/admin` 仪表盘。仪表盘内通过卡片导航到各子页面，同时提供面包屑导航返回。

**交互说明：**
- 表单字段根据表结构动态渲染，不同类型用不同控件：
  - `text` → `<Input>`
  - `textarea`（长文本）→ `<Textarea>`，显示字数统计
  - `number` → `<Input type="number">`
  - `enum` → `<Select>` 下拉选择
  - `jsonb` → `<CodeEditor>`（monospace textarea，带格式化按钮和 JSON 校验）
  - `array` → `<TagInput>`（标签式输入）
- 必填字段标红色星号，提交时校验
- 保存成功后显示 toast 提示，不离开页面
- 底部显示该记录的变更历史（从 audit_log 表读取）

## 四、交互细节规范

### 4.1 删除确认

删除操作采用两步确认，防止误操作：

1. 点击删除图标 → 该行操作区变为「确认 / 取消」两个按钮
2. 点击确认 → 执行删除
3. 如果存在引用约束（如 segment 被 persona 引用），弹出提示禁止删除，并说明被哪些画像引用

### 4.2 批量操作

- 列表页每行左侧有复选框
- 选中行后，底部浮现操作栏：「已选 N 条 [批量删除]」
- 批量删除时同样检查引用约束

### 4.3 保存反馈

- 保存成功 → 右上角 toast 绿色提示「保存成功」
- 保存失败 → 表单顶部显示红色错误信息
- JSONB 字段格式错误 → 字段下方红色提示「JSON 格式无效」

### 4.4 空状态

- 列表无数据 → 显示空状态插画 +「暂无数据」+ [新增] 按钮
- 搜索无结果 → 显示「未找到匹配结果」+ [清除搜索] 按钮
- 导入历史为空 → 显示「暂无导入记录」

### 4.5 响应式

- 表格在移动端转为卡片式列表布局
- 仪表盘统计卡片：桌面 4 列 → 平板 2 列 → 手机 1 列
- 编辑表单在移动端全宽显示

**零冲突原则：** 新增的 API 路由和前端路由与现有系统完全独立，共享同一个 PostgreSQL 数据库和 Drizzle ORM 连接池，不需要数据迁移或表结构变更（仅新增 `import_jobs` 和 `audit_log` 两张辅助表）。
