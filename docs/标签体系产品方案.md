# 射击品类 AI 模拟用户：标签体系产品方案

> 版本：v1.0  
> 日期：2026-07-27  
> 负责人角色：产品经理 × 用研专家  
> 适用范围：群体画像检索、画像生成、AI 对话人设、证据溯源与评测

## 1. 方案结论

标签体系采用“两层标签 + 一条心智链”的结构：

1. **产品检索层**：用户在前台直接选择的 5 个主维度——游戏诉求、游戏能力、游戏风格、平台偏好、模式偏好。
2. **研究解释层**：后台用于聚类、解释和评测的扩展维度——客观属性、游戏资产、社交与内容、商业化、产品偏好、甜区体验等。
3. **冰山心智链**：M1 动机 → M2 期待 → M3 认知 → M4 感受 → M5 行为，用来解释“为什么形成这个画像”，不作为简单筛选项平铺。

这样既能保持前台选择器足够简单，又能覆盖当前测试题工作簿中的全部 122 道题。

## 2. 设计依据

### 2.1 枪战分析框架

原框架包含四个核心研究模块：

- 枪战游戏诉求：一般游戏诉求、竞技诉求、游戏风格和游戏场景。
- 枪战游戏资产：时间、能力、精力、情绪、金钱。
- 枪战游戏能力：战斗场景、游戏技巧、基础认知能力。
- 甜区体验：数量、长度和质量，其中质量通过心流体验衡量。

### 2.2 冰山模型

- M5 行为/应对：可观察的外显行为。
- M4 感受：游玩过程中的即时情绪。
- M3 认知/观点：玩家解释游戏、自己和他人的方式。
- M2 期待：玩家认为游戏、队友或自己“应该怎样”。
- M1 诉求/动机：驱动行为的深层原因。

### 2.3 测试题覆盖

当前工作簿实际包含 122 道有效题：

| 题组 | 数量 | 主要覆盖内容 |
|---|---:|---|
| 一致性测试 | 31 | 城市等级、能力、动机、风格、资产、平台、社交、内容、付费 |
| 游戏立项 | 20 | 子品类、题材、美术、创新融合、迁移、平台与付费 |
| 玩法设计 | 30 | 视角、节奏、模式、地图、角色、武器、载具、难度、社交、甜区、痛点 |
| 运营与商业化 | 20 | 付费、皮肤、战令、抽奖、活动、版本、召回、公平、公会 |
| 市场营销 | 21 | 卖点、素材、KOL、明星、IP、渠道、品牌、电竞、UGC |

> 风险提示：项目 README 写有 142 道题，但当前 Excel 仅识别到 122 道。正式验收前应向题库负责人确认是否缺少 20 道或 README 尚未更新。

## 3. 标签总体架构

| 层级 | 用途 | 是否前台可选 | 更新方式 |
|---|---|---:|---|
| A. 来源与客观属性 | 证据追踪、样本约束、基础画像 | 部分 | 从原文直接提取 |
| B. 五个主筛选维度 | 快速匹配画像 | 是 | AI 标注 + 聚类统计 + 人工校验 |
| C. 扩展研究维度 | 深度解释、业务测试、二级筛选 | 默认折叠 | AI 标注 + 评测修正 |
| D. M1–M5 心智链 | 解释人设和生成回答 | 否，以画像详情展示 | 多条证据聚合 |

### 3.1 标签值的通用状态

每个标签除具体值外，还必须支持：

- `unknown`：原文没有足够信息。
- `mixed`：存在稳定的双重偏好，而非单一值。
- `context_dependent`：随模式、平台、熟人是否在线等情境变化。
- `conflict`：同一用户的多条证据直接矛盾，需要人工复核。

严禁为了“填满画像”把 `unknown` 强行推断成某个确定值。

## 4. 五个主筛选维度

## 4.1 游戏诉求（多选、有主次）

### 值域

| 标签值 | 产品显示名 | 判定要点 |
|---|---|---|
| `ability_growth` | 能力成长 | 重视练习、变强、掌握技巧和自我突破 |
| `competitive_proof` | 竞技证明 | 通过胜利、段位或击败强者证明自己 |
| `dominance` | 支配优越 | 享受压制、碾压和高于他人的优越感 |
| `team_cooperation` | 团队协作 | 乐趣来自共同完成挑战和配合取胜 |
| `social_belonging` | 社交归属 | 游戏用于维持朋友关系或进入圈层 |
| `stimulation` | 射击爽感 | 追求射击、破坏、速度和即时刺激 |
| `relaxation_escape` | 放松逃避 | 解压、消磨时间、从现实压力中抽离 |
| `strategy_mastery` | 策略掌控 | 喜欢分析、布局、资源与局势判断 |
| `exploration_collection` | 探索收集 | 喜欢发现内容、组合、地图和收集物 |
| `narrative_immersion` | 叙事沉浸 | 被世界观、角色和故事吸引 |
| `sensory_aesthetics` | 视听审美 | 主要受画面、音效、动作和风格吸引 |
| `expression_creation` | 表达创造 | 重视外观定制、建造、UGC 和自我表达 |

### 选择规则

- 前台允许多选，最多 3 个。
- 选择后需要标记一个“首要诉求”；未标记时按画像权重自动排序。
- `competitive_proof` 与 `team_cooperation` 可以共存，但分别代表个人成就和集体完成，不得合并。
- `social_belonging` 与 `team_cooperation` 可以共存：前者关注关系，后者关注合作过程/结果。
- `ability_growth` 与 `competitive_proof` 可以共存：前者关注成长，后者关注胜负证明。

## 4.2 游戏能力（单选等级 + 多选技巧）

### 综合等级

| 标签值 | 产品显示名 | 建议判定 |
|---|---|---|
| `novice` | 新手 | 尚未稳定掌握规则和基础操作；经常因门槛受挫 |
| `basic` | 入门 | 能完成对局，但枪法、信息或决策仍明显不稳定 |
| `intermediate` | 进阶 | 有稳定主玩产品和基本技巧，能自我诊断短板 |
| `advanced` | 高手 | 多项技巧稳定、理解版本和战术，表现显著高于平均 |
| `expert_competitive` | 专家/竞技级 | 高段位、赛事或半职业证据充分 |
| `unknown` | 未知 | 只有自称，没有行为、段位或他人评价支撑 |

### 技巧标签

- 枪法：拉枪、微调瞄准、压枪、跟枪、预瞄。
- 身法：基础组合、复杂身法、闪身、急停、移动中控枪、快速反应。
- 信息获取：听声辨位、复杂场景识敌、状态/资源信息收集。
- 战场策略：敌情预测、投掷物/技能使用、路线规划、战撤决策、有利位置选择、地图记忆。
- 品类知识：规则目标、核心机制、角色/武器/版本理解。

### 选择规则

- 综合等级前台单选；技巧强项和短板分别允许最多选 3 个。
- 不能仅凭“玩得久”判为高手。
- “职业级”必须有赛事、职业/半职业经历或可核验的顶级段位证据，不能由自信语气推断。

## 4.3 游戏风格（3 组双极轴）

每组只能选择一个极端或中间态：

| 轴 | 左端 | 中间 | 右端 |
|---|---|---|---|
| 战斗倾向 | 苟活避战 | 灵活平衡 | 主动求战/刚枪 |
| 决策方式 | 仔细思考/策略 | 情境切换 | 本能快速反应 |
| 取胜方式 | 团队协作取胜 | 团队个人平衡 | 个人能力取胜 |

另设两组扩展风格：

| 轴 | 左端 | 中间 | 右端 |
|---|---|---|---|
| 成长方式 | 数值养成 | 混合 | 操作技巧对抗 |
| 社交方式 | 熟人开黑 | 均可 | 陌生人/单人 |

### 互斥规则

- 同一条双极轴的两个极端互斥，例如不能同时选“苟活避战”和“主动刚枪”。
- 不同轴之间不互斥，例如“主动刚枪 + 团队协作”是有效组合。
- 如果原文明确表明按模式变化，应标为中间态并记录条件，例如“排位苟、娱乐模式刚”。

## 4.4 平台偏好（主选 + 次选）

值域：

- PC
- 主机
- 手机
- 多平台均衡
- 云游戏/其他
- 未知

规则：

- 必须区分“当前使用平台”和“真实偏好平台”。因设备、时间或朋友限制而使用手机，不等于偏好手机。
- 前台主选 1 个，可补充次选 1 个。
- 平台选择原因作为扩展标签：操作精度、便携、社交圈、设备成本、内容生态、性能表现。

## 4.5 模式偏好（单选主结构）

| 标签值 | 产品显示名 |
|---|---|
| `pve_only` | 纯 PVE |
| `pve_main` | PVE 为主 |
| `balanced` | PVP/PVE 均衡 |
| `pvp_main` | PVP 为主 |
| `pvp_only` | 纯 PVP |
| `context_dependent` | 随场景变化 |

二级模式标签允许多选：团队竞技、爆破、BR/战术竞技、搜打撤、大战场、合作 PVE、剧情 PVE、Boss/刷装、娱乐模式、开放世界。

互斥规则：

- 五档主结构单选。
- “纯 PVE”与任何 PVP 主结构互斥；“纯 PVP”与任何 PVE 主结构互斥。
- 二级模式可多选，但必须保留喜欢/回避/未体验三种状态，不能把“玩过”当作“喜欢”。

## 5. 扩展研究维度

这些标签默认不占据首页首屏，可在“更多筛选”或画像详情中展示。

### 5.1 客观属性

- 地域与城市等级：一线/新一线、二线、三线及以下、海外、未知。
- 生活阶段：学生、初入职场、稳定职场、育儿家庭、其他。
- 设备环境：固定桌面、客厅主机、移动碎片、网吧/公共设备。
- 游戏经历：射击入坑年限、主玩产品、活跃频率、段位、付费档位。
- 社交结构：固定队、熟人偶尔开黑、路人组队、单人/孤狼、公会。

### 5.2 游戏资产

每类资产采用 `充足 / 有约束 / 严重稀缺 / 未知` 四档：

- 时间资产：总游戏时长、连续时间块、可接受单局时长。
- 能力资产：上手难度、对抗困难、学习成本。
- 精力资产：注意力消耗、长时游玩疲劳。
- 情绪资产：挫败、团队压力、负面情绪恢复能力。
- 金钱资产：价格敏感、可接受付费档位。

### 5.3 产品与玩法偏好

- 题材：现代军事、历史战争、近未来科幻、末日废土、奇幻/二次元、恐怖。
- 美术：高写实、半写实、风格化、卡通/Q版、二次元。
- 视角：FPS、TPS、自由切换。
- 节奏：低/高 TTK；短/中/长对局；淘汰出局/快速复活。
- 地图：近/中/远距离；简单/复杂地形；室内 CQB/城市巷战/开阔大战场。
- 系统：英雄技能、武器改装、载具、可破坏环境、动态天气、辅助瞄准、新手保护。
- 门槛与容忍：学习成本、匹配等待、外挂、性能、强制组队。

### 5.4 商业化与运营

- 付费水平：不付费、低付费、中付费、高付费、未知。
- 付费动机：审美自用、社交展示、收藏限定、支持内容、效率/成长。
- 付费方式：直购、战令、订阅、抽奖、买断。
- 公平边界：仅外观可接受、轻度便利可接受、数值付费可接受、任何优势付费都拒绝。
- 价格敏感：记录原文中的价格锚点，不跨币种随意换算。
- 运营偏好：活动、新内容、段位重置、召回、公会/社交运营。

### 5.5 内容与营销

- 信息渠道：B站、抖音/短视频、直播、朋友口碑、应用商店、社区/论坛、媒体。
- 内容偏好：技术教学、搞笑整活、深度评测、电竞、高光实机、CG、UGC。
- 信任来源：熟人、专业评测、技术 KOL、娱乐 KOL、电竞选手、明星、厂商品牌。
- 联动偏好：日漫、欧美影视、潮牌、音乐人、主播/电竞选手。
- 转化链路：看到 → 关注 → 搜索 → 下载 → 留存 → 付费。

### 5.6 甜区与心流

- 甜区阶段：新手理解期、快速进步期、稳定精通期、平台期、流失期。
- 甜区数量：能带来明确成长反馈的技巧数量。
- 甜区长度：从开始学习到明显平台期的持续时间。
- 甜区质量：目标清晰、反馈即时、技巧挑战平衡、控制感、专注、行动意识融合、忘我、时间感变化、自目的体验。

## 6. 标签选择器交互

### 6.1 默认状态

- 所有主维度默认为“不限”，不得默认替用户选择画像。
- 首屏展示 5 个主维度；扩展维度折叠在“更多筛选”。
- 顶部持续显示匹配画像数和匹配样本数。

### 6.2 标签状态

每个标签有四态：

1. 未选：普通描边。
2. 选中：高亮填充并显示取消入口。
3. 禁用：降低透明度，悬停显示冲突原因。
4. 无结果：可以保留选中，但显示“当前组合无画像”，提供撤销建议。

### 6.3 实时匹配反馈

每次选择后返回：

- 匹配画像数。
- 匹配语料样本数。
- 每个画像的匹配度。
- 造成结果骤减的最近一个条件。
- 无精确匹配时的相近画像和放宽建议。

### 6.4 匹配逻辑

建议采用“硬过滤 + 软排序”：

1. 模式主结构、明确互斥标签用于硬过滤。
2. 诉求、风格、平台、技巧等用于加权相似度排序。
3. 首要诉求权重最高，其次为模式、风格、能力、平台。
4. 不确定标签不作为排除条件。

建议初始权重：

| 维度 | 权重 |
|---|---:|
| 首要诉求 | 30% |
| 模式偏好 | 20% |
| 游戏风格 | 20% |
| 游戏能力 | 15% |
| 平台偏好 | 10% |
| 扩展条件 | 5% |

该权重仅作为 MVP 起点，后续根据点击、访谈成功率和评测结果调整。

## 7. 组合规则

### 有效组合示例

- 能力成长 + 主动刚枪 + 个人能力取胜 + PC + PVP 为主。
- 社交归属 + 团队协作 + 熟人开黑 + 手机 + PVP/PVE 均衡。
- 放松逃避 + 苟活避战 + 手机 + PVE 为主 + 时间资产稀缺。
- 策略掌控 + 仔细思考 + 团队协作 + PC + 搜打撤。

### 冲突组合

| 冲突 | 处理 |
|---|---|
| 纯 PVE + PVP 为主/纯 PVP | 禁用后选项并解释 |
| 苟活避战 + 主动刚枪 | 同轴互斥，保留最近选择 |
| 仔细思考 + 本能反应 | 同轴互斥；允许改选“情境切换” |
| 团队协作取胜 + 个人能力取胜 | 同轴互斥；允许改选“平衡” |
| PC 单一偏好 + 手机单一偏好 | 改为“多平台”或设置主/次平台 |

### 非冲突但需解释

- 新手 + 主动刚枪：可能是低能力但高进攻倾向。
- 放松逃避 + 高竞技段位：可能技术很强，但当前游玩动机是放松。
- 社交归属 + 单人游玩：可能朋友流失后被迫单人，需记录时间条件。

## 9. 产品验收标准

- 五个主维度均有“不限/未知”处理，不强迫选择。
- 同轴互斥和 PVP/PVE 冲突能在界面即时反馈。
- 任意组合都能返回精确匹配、近似匹配或明确的空状态。
- 标签详情可以追溯到定义和证据，不展示无证据的确定结论。
- 122 道现有测试题涉及的区分维度均能映射到主标签、扩展标签或 M1–M5。
- 标签版本号随画像、标注和评测结果一同保存，避免规则更新后无法复现。

## 10. 待团队确认

1. 题库是以当前 122 道为准，还是另有包含 142 道的版本。
2. “城市等级”是否允许出现在前台更多筛选中，涉及隐私与刻板印象风险。
3. 是否保留现有代码中的“职业级”；本方案建议改为“专家/竞技级”并提高证据门槛。
4. 主选择器最多允许几个诉求标签，建议 MVP 为 3 个。
5. 标签匹配是面向画像还是直接面向原始用户片段；本方案建议先匹配画像，再展示证据样本量。
