## 二、问题详情

### 🔴 问题 1：AI 标注未完成（严重）

**现象**：44/61 个文件的标注覆盖率 < 95%，整体覆盖率 89.1%。最严重的文件：
- Deadlock竞品研究/座谈会笔录-G2.json：48/158 (30.4%)
- 搜打撤品类研究/国内/座谈会笔录-G1.json：82/211 (38.9%)
- Deadlock竞品研究/座谈会笔录-G1.json：109/244 (44.7%)

**根因**：`label_all_v3.py` 的断点续跑机制存在缺陷。检查 checkpoint 文件（`.checkpoint/` 目录，17,306 条记录）后发现：
1. Checkpoint 只记录 segment_id 和 `done: true`，但未验证标注是否真的写入了输出文件
2. 当 API 调用失败（3 次重试后），该 segment 被标记为 `empty_annotation`（api_error），但 checkpoint 仍记录为 "done"
3. 如果脚本被中断后重新运行，`--resume` 只检查输出文件是否存在（不检查内容完整性），导致已存在但内容不完整的输出文件被跳过

**修复方案**：
1. **修改 `label_all_v3.py` 的 `--resume` 逻辑**：不仅检查输出文件存在，还要检查文件内所有 kept segment 是否都有有效的 annotation（非 api_error 标记）
2. **重新运行标注**：删除不完整的输出文件后，用 `--resume` 重跑，或修改脚本支持强制重新标注未完成部分
3. **建议新增 `--retry-failed` 参数**：只重新标注标记为 api_error 的 segment

**现象**：`data/embed/profiles/` 下有 14 个项目目录，但所有目录内都没有 `profile_embeddings.json` 和 `profile_embeddings.npy` 文件。

**影响**：无法进行 HDBSCAN 聚类，无法生成 persona 分组。

**修复方案**：运行 `embed_server.py` 或对应的 profile embedding 生成脚本。需要确认生成 profile embedding 的入口脚本。

### 🟡 问题 4：清洗目录存在重复文件

**现象**：`data/群体画像v2.0_cleaned/` 目录下同时存在两类文件：
- `.json` 文件（62 个）：包含所有 cleaning_status（kept + removed_noise + removed_irrelevant 等），**不含** summary 字段
- `_cleaned.json` 文件（61 个）：仅含 kept + needs_review 的 segment，**含** summary 字段，符合规范 v2.1-demo

**根因**：`.json` 文件是清洗脚本的中间产物或旧版本输出，`_cleaned.json` 是规范要求的最终输出。`label_all_v3.py` 的 `find_cleaned_files()` 函数正确地只读取 `_cleaned.json`（line 144），所以标注流程不受影响。但重复文件占用磁盘空间，且容易引起混淆。

**修复方案**：
1. 确认 `.json` 文件不再被任何脚本引用后，删除它们
2. 在 `clean_segments_v2_demo.py` 中确保只输出 `_cleaned.json` 格式

### 🟡 问题 5：Profile 生成缺少规范要求的字段

**现象**：生成的 Profile 文件中，traits 的 `label` 和 `inference_level`/`inference_type` 字段缺失。

**规范要求**（`docs/用户画像Profile生成规范.md` v1.0）：
- 每个 Trait 应包含 `label`（简短标签）和 `inference_level`（L1/L2/L3）
- 当前输出中 traits 有 `evidence`、`confidence`、`temporal_scope` 但缺少 `label` 和 `inference_level`

**修复方案**：检查 `generate_profiles.py` 中的 System Prompt 和 trait 解析逻辑，确保 API 返回的 trait 包含 `label` 和 `inference_level` 字段。

### 🟡 问题 6：标注规范 v3.1 的 framework 维度为空

**现象**：已标注的 segment 中，`annotation.framework` 经常为空对象 `{}`。例如 IMUR 文件（100% 标注完成）中，所有 segment 的 `framework` 都是空对象。

**根因**：可能是 DeepSeek API 的 System Prompt 没有强制要求 framework 维度标注，或 API 输出中 framework 被省略。需检查 `label_demo_v3.py` 中的 `SYSTEM_PROMPT`。

**修复方案**：检查并加强 System Prompt 中 framework 维度的要求，确保 API 返回完整的 7 维度标注。

### 🟡 问题 7：流水线调度脚本与实际脚本不匹配

**现象**：`run_pipeline.sh` 中引用的 `embed_server.py` 是嵌入服务（API 服务），不是 profile embedding 生成脚本。`run_pipeline.sh` 缺少 profile embedding 生成步骤。

**修复方案**：更新 `run_pipeline.sh`，明确区分：
- Segment Embedding 生成（`embed_segments.py`）
- Profile Embedding 生成（需要确认脚本或新增）
- 嵌入服务启动（`embed_server.py`）

**影响**：所有数据停留在文件系统，无法通过 API 查询和使用。
