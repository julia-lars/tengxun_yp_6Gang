# 证据匹配度优化方案

## 当前问题

### 数据流现状
```
用户问题 → embedQuery() 向量化 → pgvector 向量检索（cosine距离）
         → RRF 融合 BM25 → 返回 Top 15 条 source_segments 作为"证据"
         → 证据塞入 System Prompt → LLM 生成回答
         → 前端显示每条证据的"匹配 XX%"（用的是 pgvector 向量相似度）
```

### 核心矛盾
前端显示的"匹配 XX%"是 **用户问题向量 ↔ 证据文本向量** 的余弦相似度，不是"证据是否真的支撑了 AI 回答"。结果：
- 语义相近但毫不相关的证据 → 显示 100% 匹配
- 真正支撑回答的证据 → 可能只有 72% 匹配

例子：
- 用户问："射击游戏最让你开心的是什么？"、AI 回答："跟朋友玩"
- 证据 A："穿越火线：放松，暗区：没感觉，DF：新鲜" → 匹配 100%（都讨论射击游戏体验，向量接近）
- 证据 B："每次和朋友一起玩是最开心的，团队合作" → 匹配 72%（用词不同但真正相关）

---

## 方案设计

### 核心思路：匹配度改为衡量"证据 ↔ AI 回答"的相关性，而非"问题 ↔ 证据"的向量相似度

**为什么是"证据 ↔ 回答"而不是"问题 ↔ 证据"？**
- 用户看到的是 AI 的回答 + 证据卡片，他关心的是"这条证据能支撑这个回答吗？"
- RAG 检索（问题→证据）的相似度在前端对用户没有意义，用户只知道 AI 最终说了什么

### 两阶段改造

#### 阶段一：RAG 检索后，用 LLM 对每条证据与 AI 回答做匹配度评分（推荐先做）

**流程变化：**
```
用户问题 → 向量检索 → 证据 → LLM 生成回答
                              ↓
                    回答生成后，LLM 对每条证据打分：
                    "这条证据是否支撑了回答中的某个观点？0-1 分"
                              ↓
                    前端显示 LLM 打分的匹配度（替代向量相似度）
```

**具体实现：**

1. 在 `streamChat` 中，LLM 回答生成完毕后，新增一个异步步骤：用另一个 LLM 调用（轻量 prompt）对每条证据 vs 回答做匹配度评分
2. 评分 prompt 示例：
   ```
   AI 回答：{answer}
   证据原文：{evidence_text}
   
   请判断这条证据是否支撑了 AI 回答中的某个具体观点。
   - 1.0：证据直接支撑了回答中的核心观点，引用关系明确
   - 0.7-0.9：证据与回答部分相关，但不够直接
   - 0.4-0.6：证据与回答话题相近但未直接支撑
   - 0.0-0.3：证据与回答基本无关
   
   只输出一个 JSON：{"score": 0.8, "reason": "证据提到了朋友组队，支撑了回答中'跟朋友玩排第一'的观点"}
   ```

3. 用评分结果覆盖 `similarity` 字段，前端无需改动

**工作量：** 主要改动 `agent-chat.ts` 的 `streamChat` 函数，新增一个 `evaluateEvidenceRelevance()` 函数
**代价：** 每条消息额外 1 次 LLM 调用（可并行处理多条证据，或用便宜的模型）

#### 阶段二：前端展示优化（配套）

1. **匹配度文案改为"相关性"而非"匹配"**：`匹配 72%` → `相关性 72%`
2. **增加匹配理由 tooltip**：hover 显示 LLM 给出的简短理由
3. **证据等级与匹配度脱钩**：`matchLevel`（直引/部分关联/推断）改为基于 LLM 判断而非 fixed 阈值

## 备选方案：轻量级方案（不需要额外 LLM 调用）

如果不想增加 LLM 调用成本，可以用 **Cross-Encoder 精排分数**替代向量相似度：
- 启动 `rerank_server.py`（BGE-Reranker-v2-m3）
- Reranker 对 (用户问题, 证据文本) 做 Cross-Encoder 打分，比向量相似度准得多
- 修改 `rerankEvidence` 把精排分数写回 `similarity` 字段

**缺点：** Cross-Encoder 衡量的是"问题 ↔ 证据"的相关性，不是"回答 ↔ 证据"，仍然存在偏差（只是比向量相似度好）
**优点：** 零额外 LLM 成本，只需启动 rerank 服务

---

## 推荐路径

1. **先做备选方案**（启动 rerank 服务 + 精排分数覆盖 similarity）— 成本最低，立即改善
2. **再做阶段一**（LLM 证据-回答匹配度评分）— 彻底解决准确性问题
3. **最后做阶段二**（前端展示优化）— 锦上添花
